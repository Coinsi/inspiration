# Inspiration 交互现状清单

日期：2026 年 10 月 12 日

当前复杂度主要来自入口命名不一致、同一创作对象分散在多个页面、任务与设置的作用范围不直观。不能仅靠减少侧栏菜单或调整样式解决，也不应在梳理前删掉已有能力。

本轮基于 `C:/Code/Python/inspiration` 当前工作区代码，检查路由、导航、页面及主要交互组件。只新增分析文档，未修改产品代码。以下“已确认”指代码能确认的结构或行为；没有把静态审查当成浏览器操作验收。不同权限、空项目、已有素材以及运行中状态的实际可见按钮，仍需后续逐一走查。

## 1 导航全貌

项目内有 24 个具名路由（包括详情、导入和回收站）；侧栏有 8 个一级分组。分组不是 8 个单独功能，每组还可能有页面、标签和详情面板。

| 侧栏一级分组 | 子页面或默认入口 | 需要用户理解的区别 |
| --- | --- | --- |
| 工作台 | workbench | 直接生成、项目概览、继续创作三个用途共存 |
| 故事与剧本 | narrative、scripts、bible | 小说章节、可编辑剧本、故事设定是不同对象 |
| 素材库 | assets、library、evidence、assets/trash | 角色资产、媒体文件、身份观察、资产回收站 |
| 镜头创作 | storyboard、shots、director | 分镜编辑、镜头看板与详情、3D 预演 |
| 自由画布 | canvas | 自由组织内容和执行节点流程 |
| 剪辑成片 | cuts、transcriptions | 时间线编排与独立字幕任务 |
| 创作助理 | agent | 自然语言任务、工具执行、人工审批 |
| 创作工具 | skills、prompts | 技能包和提示词片段 |

补充入口：

- 顶栏项目菜单：项目资料与封面、创作默认项、渠道与模型、成员与权限、更多项目设置、切换项目。
- 顶栏：任务中心、查找功能、用户菜单。侧栏另有快速导航和所有项目。
- 用户菜单：个人设置、外观与语言、平台管理（管理员可见）、产品官网、退出登录。
- 素材页面内横向标签：AI 生成、角色与场景、素材库。AI 生成路由存在，但不属于当前侧栏的任何一级分组。
- 快速导航：按名称和关键词查找功能入口，不是跨素材、剧本和作品的统一内容搜索。

依据：[分组配置](../../frontend/src/lib/workspace-stages.ts)、[完整导航目录](../../frontend/src/lib/workspace-navigation.ts)、[路由](../../frontend/src/App.tsx)、[项目外壳](../../frontend/src/components/AppShell.tsx)、[素材标签](../../frontend/src/components/MaterialTabs.tsx)。

## 3 高频操作的输入和去向

### 生成一张图或一段视频

工作台输入描述 → 选择图片/视频、模型、画面参数、参考 → 开始创作 → 本页查看任务和结果 → AI 生成页汇集 → 用作参考返回工作台，或查看来源任务。

镜头和资产也有独立生成面板；画布还可以从节点发起生成。多入口本身并非错误，真正要检查的是模型选择、结果命名、参考选取、保存说明和失败恢复是否一致。

依据：[工作台创作组件](../../frontend/src/components/workbench/WorkbenchComposer.tsx)、[通用生成面板](../../frontend/src/components/GenerationPanel.tsx)、[生成素材页](../../frontend/src/pages/GeneratedLibrary.tsx)。

### 从小说推进镜头

小说导入 → 选择章节 → 生成剧本 → 剧本编辑 → 拆场次/镜头 → 审阅并应用建议 → 分镜 → 镜头生成和候选选择 → 时间线编辑 → 导出。

“抽实体 → 落为资产”和“故事设定 → 转为资产”是相关支路，不应把所有步骤都解释成任何创作都必须经过。当前工作台下一步推荐根据项目数据是否存在判断；空项目会推荐故事阶段，并不是识别用户意图后决定入口。

依据：[工作台 next 逻辑](../../frontend/src/pages/Workbench.tsx)、[剧本编辑器](../../frontend/src/pages/ScriptEditor.tsx)、[设定页](../../frontend/src/pages/StoryBible.tsx)。

### 使用一个已有视频片段

项目素材导入 → 等待基础处理 → 在“我的素材”预览，或到“搜索素材”检索 → 打开片段 → 选择镜头并引用 → 打开镜头继续。

素材详情还提供索引/处理、身份观察、转写和版本管理。字幕校对后有单独“发布到检索”动作。需要验证用户是否能在一个位置知道“能播放、能按字幕搜、能按画面搜”分别何时可用，而不用学习服务名称。

依据：[素材页](../../frontend/src/pages/MediaLibrary.tsx)、[检索组件](../../frontend/src/components/LibrarySearch.tsx)、[处理组件](../../frontend/src/components/LibraryProcessing.tsx)、[字幕页](../../frontend/src/pages/Transcriptions.tsx)。

### 连接模型并开始创作

项目菜单“渠道与模型” → 设置“模型服务” → 我的模型服务／项目默认模型／项目专用服务／高级路由 → 连接服务或管理模型 → 返回创作选择器。

创作选择器也提供连接管理入口。问题不在于没有入口，而在于进入项目设置后仍需区分个人连接、项目连接、项目默认项、路由。不能仅通过统一“保存”按钮文字解决。

依据：[设置](../../frontend/src/pages/Settings.tsx)、[渠道组件](../../frontend/src/components/ModelChannels.tsx)、[个人模型服务](../../frontend/src/components/PersonalModelServices.tsx)、[选择器](../../frontend/src/components/workbench/ComposerModelPicker.tsx)。

## 4 已确认的结构问题与研究优先级

这里的优先级用于安排后续研究，不是已经批准的改版方案。

| 优先级 | 代码中确认的现象 | 可能造成的困惑 | 后续需要验证 |
| --- | --- | --- | --- |
| 高 | assets 在导航叫“资产库”，素材标签叫“角色与场景”，工作台叫“角色与资产” | 以为是不同功能；找图前先判断分类 | 统一术语能解决多少问题，是否仍需调整入口 |
| 高 | 侧栏“素材库”首个路由是 assets；library 页标题也叫“素材库” | 点素材库却先看到结构化角色资产 | 用户对“素材”的自然分类是什么 |
| 高 | generated 有路由和横向标签，但未归入侧栏分组 | 查看生成结果时失去侧栏所属位置 | 是否应成为统一素材视图中的来源筛选 |
| 高 | 剧本按钮出现“抽实体”“落库场次/镜头”“落为资产” | 不知道执行结果，也难判断是否要点 | 用实际创作结果命名，是否还需保留两段审批 |
| 高 | 模型设置同时包含个人和项目配置 | 不清楚保存作用范围、哪个配置被使用 | 在入口和保存结果处如何明确范围及优先级 |
| 高 | 任务中心另跳转到转写、画布、助理、素材处理 | 查进度必须先知道任务属于哪个系统 | 是否能提供统一总览，再跳到专业详情 |
| 中 | 保存、提交版本、锁定分别调用不同资产接口；字幕保存和发布检索也不同 | 以为一次保存已经完成全部动作 | 哪些可自动完成，哪些需显式业务确认 |
| 中 | 工作台、镜头/资产、画布都有生成入口 | 同样生成图片，需要学习不同操作方式 | 对同一任务并排走查，找出必须不同和可以统一的部分 |
| 中 | 小说、项目、资产、媒体文件有各自回收流程 | 不知道删除内容去哪里恢复 | 是否需要统一入口而保留对象恢复规则 |
| 中 | 侧栏、快速导航、项目菜单、页内标签、工作台阶段卡同时提供入口 | 多条路径未必更好找；名称差异加剧记忆负担 | 哪些是有效快捷入口，哪些重复制造选择 |
| 中 | 空项目“继续创作”按小说/剧本/资产/镜头存在性推荐 | 想用现有视频创作的人可能被引向小说 | 需要意图入口还是更合适的空状态提示 |

## 5 应保留的已有设计

- 用户信息、外观语言已进入顶栏用户菜单，项目配置通过项目菜单进入。
- 画布、导演、剪辑已有沉浸式布局，专业功能不必一律删掉。
- 生成素材可回到来源任务，任务详情可回到创作位置；这些是整理流程的重要基础。
- 很多页面已经有草稿恢复、错误重试和禁用条件，不能在“简化”时把恢复能力抹掉。
- 媒体删除前会展示引用关系；降低操作成本不应以破坏引用安全为代价。
- AI 建议、正式写入、审阅确认有实际业务区别，可以优化表达，不能直接等同为重复按钮。

## 6 下一轮参考研究和走查清单

本轮尚未完成参考产品实操研究，不把既往截图当作它们当前全部交互的证据。下一轮重点看影策；其他产品应按“素材检索、创作生成、时间线剪辑”的具体任务选取，不按页面外观相似度挑选。

同一任务在本项目和参考产品各走一遍，记录：起点、当前主操作、需要先理解的概念、页面切换、保存反馈、结果去向、错误恢复。不能把源码控件数换算成点击数。

| 测试情境 | 要回答的问题 |
| --- | --- |
| 新用户只有一句创意，生成图片 | 是否能不理解项目渠道和资产模型就完成 |
| 已有小说，做一个镜头 | 能否解释下一步；有没有不必要的手工搬运 |
| 已有长视频，找一句台词对应片段 | 上传处理状态是否清楚；未索引时是否有可执行指引 |
| 生成结果再作为参考 | 能否找到原结果；是否要求重新上传或另建对象 |
| 任务失败或页面关闭后回来 | 能否找到任务、保留输入并继续；是否会重复收费提交 |
| 切换项目后使用已配置的模型 | 能否判断哪个配置生效、权限和作用范围是什么 |
| 删除正在被引用的素材 | 能否理解影响并取消、解除引用或恢复 |

在这些任务完成走查前，不预定“三个入口”或新的首页结构。先决定哪些问题靠术语可解决，哪些必须调整流程，哪些只是专业功能需要按需展开。

## 7 控件原始索引

[控件源码索引 CSV](2026-10-12-controls.csv) 包含 114 个 TSX 文件中的 1314 个交互节点定义，记录文件、行号、节点类型、文案/表达式、动作、禁用条件和代码片段。

这是供后续逐项核对的机械索引，**不是用户同时看见 1314 个按钮**：它包含输入框、链接、条件分支、复用组件、管理端和可能未使用的旧组件；列表模板运行时可生成多项，也可能一个都不显示。动态标签和配置驱动菜单未完全展开；祖先节点的条件可见性和禁用状态未全部求值。`label_zh` 仅替换静态翻译键，仍可能包含中英文分支或 JSX，不能直接当成最终显示文案。

主要清单已经归并了用途；后续浏览器走查应在此基础上补“实际可见状态、默认主操作、操作反馈”，不能用节点数量证明设计好坏。
