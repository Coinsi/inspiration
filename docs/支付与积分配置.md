# 支付与积分

网页版和桌面端共用「我的积分」。用户选择积分包，下单后打开收银台或扫码付款。订单会分别显示付款已确认和积分已到账，也可以查询历史订单或申请退款。

## 平台管理

超级管理员在「平台管理 → 支付与积分」管理积分包、支付渠道、订单退款和待核对的生成积分。数据库迁移 `0064_billing` 创建订单、退款和积分流水表。新环境默认关闭购买和付费生成。

1. 配置服务端现有的 `CREDENTIALS_FERNET_KEY`。支付渠道凭证使用该密钥加密，保存后后台接口仅返回渠道的公开配置。
2. 在支付设置里保存公开访问的 HTTPS 站点地址。该地址用于支付返回和通知。
3. 新建渠道并输入支付平台签发的凭证。可以为同种渠道添加多个商户实例，用户下单时选择渠道。
4. 建立同币种的积分包，并打开「开放积分购买」。调整价格只影响之后新建的订单，历史订单保留创建时的金额和积分。
5. 用商户测试环境或独立联调环境核验下单、通知、查单、取消及退款，再打开「平台模型按积分扣费」。

| 渠道 | 付款方式 | 商户平台配置 |
| --- | --- | --- |
| Stripe | 托管 Checkout 银行卡支付 | 从添加渠道表单复制通知地址，在 Stripe 注册 Webhook。启用 `checkout.session.completed`、`checkout.session.async_payment_succeeded`、`checkout.session.async_payment_failed`、`checkout.session.expired`，将签名密钥填回表单。 |
| 微信支付 | 人民币 Native 扫码 | 开通 Native 支付，填写商户号、应用 ID、商户证书参数、API v3 密钥及微信支付公钥。通知地址随订单提交。 |
| 支付宝 | 人民币电脑网站支付 | 开通电脑网站支付，填写应用 ID、收款账号 ID、应用私钥和支付宝公钥。通知地址随订单提交。 |

换商户时添加新的渠道实例，再停用旧实例的收款入口。历史订单继续使用原渠道查单、通知和退款。

## 订单与积分规则

- 服务器以订单保存的金额、币种和支付渠道为准，验证支付平台的通知后确认付款。同一笔订单的积分只发放一次。
- 查单与后台定时任务可以补发已付款但尚未到账的订单。取消订单以支付平台确认为准。若支付仍待核实，保留原订单状态。
- 项目内部额度和个人积分各自记录。开启扣费后，已定价的平台图片、视频生成会预留个人积分，成功后按实际线路结算。个人模型密钥和项目自带渠道使用各自的供应商额度。
- 确认未提交给供应商的任务会退回预留。供应商是否扣费无法确认时，超级管理员可以在「积分预留」核对后结算或释放，操作会记入审计。
- 退款批准后先冻结对应积分，再向原渠道退款。处理中保留冻结，退款成功后扣回，明确失败后退回。部分退款按累计退款比例计算积分，最后一次全额退完可扣回原订单全部积分。
