# 视频 Agent Harness 改造基线

日期：2026-10-23。状态：设计基线与实施对照；当前代码、已通过验收及剩余限制见 [当前实现](CURRENT_STATUS.md) 和 [实施账本](IMPLEMENTATION_PLAN.md)，新业务接入见 [扩展指南](EXTENSION.md)。设计条目本身不代表已实现或已验证。
本轮代码对照基于 `6f93785`；工作区其他进行中的修改不作为本方案的实现证据。

本文收敛用户在本项目讨论中确认的目标，以及由实现方负责的工程取舍。工程格式与编辑语义沿用 [可编辑作品工程设计](../editable-project/README.md)，已有能力及限制以 [工程当前状态](../editable-project/CURRENT_STATUS.md) 和代码为准。本文的设计术语与当前公开 API 的对应关系见当前实现文档，不以概念名称推断接口。

## 1. 产品目标与已确认规则

- 单一创作对话入口支持讨论、检索、图片、视频、音频与剪辑，支持多段对话。直接生成是单节点制作任务，仍共享上下文、权限、计费和结果归属规则。
- 用户可以只生成一份媒体；需要组合或持续编辑时建立最小作品工程，不把工程表单作为所有对话的前置条件。
- 复杂目标先给简短方案，确认后在批准范围内连续执行。明确要求生成时按已有权限、模型配置和预算直接执行；不重复要求逐工具确认。
- 新内容与修改先成为草稿或候选，用户确认后替换已采用版本。执行授权与采用确认分开；授权内允许候选作为后续制作的固定输入，但必须保留其未采用状态。
- 用户可以在执行期间补充要求、修改方向、暂停、取消或继续；系统保留原成果和未受影响的任务。
- 多 Agent 从第一版任务底座支持。先验收协调者与少量工作者的真实并行，再扩大角色、并发和影片规模。
- 对话、作品、素材、任务、工具、权限和修改记录由系统持有；换 Agent 内核不迁移这些事实到内核私有状态。
- 界面展示作品进度、候选和需要决定的问题；工具发现、任务拆分和工作者分配不转嫁给用户。

## 2. 当前可复用能力与明确断点

本节是开始改造时的代码快照；下表的断点不能当作改造后的现状。当前状态以 CURRENT_STATUS.md 为准。

| 范围 | 当前可复用能力 | 改造断点 |
| --- | --- | --- |
| 对话 | Conversation/Message、历史、作品关联、结果呈现 | 活跃任务阻止新消息；直接媒体路径不接收对话历史 |
| 工具 | 独立 registry、schema、version/group、工程工具 | 全量目录每轮加载；调用与审阅仍部分绑定 AgentRun；review 布尔值不足以描述副作用 |
| 检索 | library.search 已可被 Agent 调用 | 工具仅接部分检索路径，未统一页面已支持的全部检索能力与素材检查 |
| 生成 | GenerationJob、固定输入、供应商句柄、配额与素材存储 | Agent 生成接口未覆盖工作台参考输入能力；不同入口需要统一执行契约 |
| 工程 | 固定修订、候选、预览、采用、实例路径、部分依赖影响 | 整作品 CAS；旧基线 propose 可能被拒；缺少持久读写前提与受控整合 |
| 恢复 | 本地工程预览 outbox、租约、结果发布校验 | 不能等同于全部供应商任务与 Agent 流程已可恢复 |
| 决策 | 有限步数模型/工具循环、暂停取消与步骤记录 | 全局串行调度；无制作任务图、动态转向、产物完成验证 |

主要代码入口：`backend/app/modules/conversation/`、`agent/`、`tools/`、`generation/`、`engineering/`、`library/`。已有 GenerationJob、工程候选和费用记录继续使用，不建立重复账本。

## 3. 系统职责与可替换内核

应用的 harness 层持有任务图、授权、上下文构建、调度、用户事件与完成验证。领域工具服务持有合法业务操作。工程模块持有作品事实。Agent 内核只提出结构化决策。

内核输入至少包含：任务目标、当前计划版本、允许动作、上下文包引用、实际能力摘要、未决问题、剩余预算，以及上次动作的可核验结果。

内核输出动作需覆盖：

| 动作 | 系统行为 |
| --- | --- |
| 提出或修订计划 | 先验证能力、依赖、输入输出、范围和预算，通过后才能调度 |
| 请求工具操作 | 校验权限、副作用和输入版本，建立独立调用记录 |
| 委派子任务 | 创建明确范围、输出契约、预算及父子关系，限制深度和总并发 |
| 请求澄清或审阅 | 保存待回答的问题及适用版本，释放工作进程，等待用户事件 |
| 等待依赖 | 等待已存在的任务或事件，不虚构完成、不占用模型循环空转 |
| 建议完成 | 根据任务类型验证所需产物、约束和审阅状态，由系统改变状态 |

普通问答可在回复完成后结束；需要媒体或工程成果的任务不能靠一条 finish 文本成为成功任务。适配器支持供应商原生结构化调用或兼容 JSON，但统一经过应用协议校验。

模型请求、流式内容、工具请求和取消信号由内核适配器转换。持久恢复不依赖私有会话或隐藏推理。记录简短决策说明及证据引用即可，不把模型内部推理作为工程事实。

## 4. 决策循环与记忆有效性

每个工作任务遵循：观察当前输入 → 提出动作 → 校验与执行 → 检查产物 → 更新任务状态或计划。检查强度依据任务风险和成本安排，不要求每个无副作用查询都重复运行昂贵模型。

- 计划必须能映射到已验证的工具能力；尺寸、时长、参考输入类型、算子支持和必要素材缺失时，在派发前报告。
- 观察记录固定来源版本、媒体范围、方法、覆盖程度和不确定性。抽帧不等于检查所有帧，转写不等于听过表演。
- 记忆分为用户决定、工具观察、Agent 推断、历史摘要。均记录来源、适用范围和被替代关系；摘要不是权限来源，也不能恢复已撤回的要求。
- 上下文压缩保留有效要求、未决问题和可检索来源。需要精确信息时重新读取固定版本；无法找到时明确缺失，不补造内容。
- 监测重复调用、同一错误反复出现和没有有效产物变化的循环；在预算或尝试上限内调整策略，必要时等待用户，不无限返工。

## 5. 持久任务与控制事件

最小持久对象包含制作运行、计划修订、任务节点、依赖、执行尝试、工具调用、用户控制事件、授权记录、上下文快照引用、产物关联和检查记录。具体表结构须在编码前按事务边界细化。

任务节点至少保存所属作品/候选工作区、父任务、输入修订、读写范围、输出契约、状态、尝试、预算、计划代次与执行租约。制作执行依赖、工程内容依赖和创作关联分别建模；反馈允许修订计划，单次可执行依赖图必须可调度且无环。

- 按节点领取租约，短事务修改状态；模型调用和长渲染不持有全局数据库锁。
- 以事务投递和幂等交付协调数据库与队列。发布结果时重新检查租约、计划代次和权限，阻止旧执行者改变新状态。
- 页面关闭默认不取消后台制作。显式暂停停止后续派发，并按工具能力请求暂停或取消；未经用户继续，不因重启而解除暂停。
- 供应商无法暂停时如实展示在途状态，保留返回结果，不自动推进已暂停或已取代的计划。
- 区分未发送、提交结果未知、已接收任务句柄、执行中、接收产物和已验证可用。未知外部状态优先查询；缺少可靠查询/幂等能力时不盲目重发付费请求。
- 产物接收包含下载、完整性检查、媒体检查和持久关联。临时链接返回不等于素材已保存；接收重试不重新生成。
- 用户输入先保存有序事件，区分讨论、命令、撤回和范围变更。定向阻止受影响节点继续派发；无关任务继续。
- 同一作品的多个对话共享修改协调与采用规则；暂停一个任务不隐式暂停整个项目。

## 6. 多模态上下文与工具分层

上下文包包含明确目标、最新有效决定、必须保留项、工程固定基线、目标实例/时间/区域、相关上游产物、技能固定版本、预算与输出要求。源时间、实例时间和成片时间不能混用。

统一素材引用表示身份、固定版本、使用实例、时间范围、空间选区和用途。参考画风、参考人物、用于首帧、直接插入时间线等用途应明确。临时访问链接由受权限约束的适配器生成，不作为稳定身份。

媒体检查工具支持按任务读取元数据、关键帧、局部裁剪、试听片段、带时间码转写和已有标注。上下文构建器按模型实际输入能力发送证据，并控制内容预算；不能只给 ID 就认为模型已看过。

工具分成任务能力、业务操作和执行器三层。Agent 初始获得能力摘要，按任务发现并加载操作；无需将所有底层函数暴露给用户或每个 Agent。

工具注册契约包括输入/输出类型与版本、权限、读取与修改范围、副作用、异步行为、幂等、取消/恢复、费用规则、前后置检查、错误类别，以及可编辑产物程度。技能可以提供方法与参考，不能自行扩大权限或取得未批准的执行能力。

| 制作能力 | 必须能够对接的实际操作 |
| --- | --- |
| 素材 | 检索、核验、比较、复用或创建引用；页面和工具共享服务 |
| 图片 | 生成、参考修改、局部修复、蒙版/图层和文字；按真实执行器支持声明 |
| 视频 | 文生、图生、参考视频、局部替换与延长；能力与参考限制预检 |
| 剪辑与合成 | 裁剪、分割、拼接、排序、变速、转场、叠加与实例替换 |
| 声音 | 配音、配乐/音效接入、增益、混音、字幕/歌词对齐与同步检查 |
| 交付 | 局部预览、整体预览、工程验证、固定版本导出与成果接收 |

这里列的是接入范围，不声明这些工具全部已经实现。各工具优先返回可编辑文档、源素材与参数；只能返回合成媒体时说明其编辑边界。规划器不得调用尚未可执行的效果。

## 7. 候选协作、采用和反馈定位

- 工作 Agent 共用固定输入，各自产生候选；采用规则由工程服务执行。旧基线候选允许保存，采用时再做有效性和冲突校验。
- 保存规范操作、真实读前提、写范围、来源任务和目标工作区。先支持并行制作、集中整合；不要以取消整作品 CAS 的方式实现并发。
- 对无关修改进行受控重放与整体验证。有语义或时间依赖冲突时保留双方结果，重新规划或请求选择，不直接覆盖快照。
- 用户手改、锁定属性和已认可部分成为后续任务的保留约束。读写字段不重叠也不代表创作含义不冲突。
- 反馈绑定实例、固定版本、区间及当时预览；内容移动后更新定位，无法可靠对应时请求用户定位。
- 支持在工程可分离的镜头、音轨和图层层面采用候选。已经合成进单一媒体的内容不得假装可无损拆分。
- 撤销针对具体操作及其前提，保留期间其他有效修改。恢复旧结果使用真实已保存产物，不以相同提示词重新生成代替。
- 候选拒绝、采用、预览完成和用户回复都是可唤醒任务的系统事件；不要依靠 Agent 不断轮询猜测决定。

## 8. 质量、失败与资源策略

技术验证、创作要求验证和主观审阅分别记录。角色/服装/武器/声线等全片设定与场景状态、局部例外分开；局部完成后还需检查相邻镜头及整片衔接。检查 Agent 提供证据与建议，不取代用户采用权限。

失败报告区分参数错误、权限或前提失效、能力不支持、临时服务故障、外部状态未知、输入理解错误和效果不达标。分别采取纠正参数、重新读状态、修订计划、有限重试、查询对账、补充观察或生成差异候选。归因不确定时保留不确定性。

降级须符合原授权和保留约束。不能静默丢弃参考人物、改变内容或放宽硬性要求。允许调整的预览质量等政策由系统明确配置。

预算覆盖模型、渲染、传输、存储与返工，记录已消耗、预留和可用余额；父任务统一约束子任务。并发按项目/用户/供应商/机器资源控制，避免单个任务挤占全部队列。缓存可淘汰，工程、在途任务和审阅引用的源内容必须保留。

横竖屏、不同语言和长短版本有独立交付根与要求；共享内容升级需复核，不默认静默传播。最终导出与用户查看的固定工程版本对应，低质量预览未覆盖的检查不能标记为通过。

## 9. 演进与替换

工具、技能、模型配置、执行器和工程格式使用明确版本。新任务使用新配置，已执行结果保留来源；暂停任务恢复时校验兼容性和当前权限。

新业务通过注册类型、工具、执行器及验收用例接入。先在现有模块化单体内建立清楚边界，后续按实际负载扩容工作进程。生产不依赖任意第三方 Agent 内核的私有存储格式。

旧对话与 AgentRun 保留读取和兼容执行路径；新 harness 分阶段接管新任务。既有工程、时间线和供应商在途任务迁移必须有映射和回退方案。不能在未知外部状态下把旧任务当成新请求重发。

## 10. 实施顺序与交付门槛

| 阶段 | 主要交付 | 可操作的验收 |
| --- | --- | --- |
| A 契约与统一调用 | 内核动作协议、工具执行契约、固定引用、记忆类别、任务/控制事件结构 | 不依赖 AgentRun 调用同一工具；直接生成与 Agent 路径遵循相同参考/预算/产物规则 |
| B 首条完整协作链 | 上下文与检索检查、持久节点、协调 Agent 与至少两个工作任务、候选整合和对话进度 | 从素材查找进入制作、并行完成独立部分、合成预览；用户中途意见能被接收并作用于任务 |
| C 恢复与转向完整验收 | 局部暂停/续跑、计划修订、晚到结果隔离、费用预留、失败分类与受控重试 | 崩溃、上游未知、撤销与手改并发均有明确结果，不重复付费、不覆盖新方向 |
| D 制作质量与扩展 | 声音/画面/剪辑链完善、连续性与全片检查、多交付版本、内核替换 | 实际观看与试听完整作品；在保留其他部分前提下修改局部；替换内核可接续同一任务 |

B 阶段不是只做 UI 或模拟工作者演示；每批从界面到工具再到工程产物闭环。可靠性规则在 A 阶段定义并随 B 实现，C 是集中故障验收，不意味着此前允许遗漏幂等与版本检查。基础机制与具体制作工具共同推进。

## 11. 首期必须覆盖的反例

1. 对话前一轮的图片或视频能被下一轮实际查看并引用，而非仅复述文件 ID。
2. 任务运行时收到局部意见，无关节点继续；全局改剧本时旧依赖被正确阻止。
3. 用户连续撤回或修订意见，旧指令不能在恢复后复活。
4. 两个工作者分别修改无关部分均保留；配音变长时旧字幕被判定需要重新对齐。
5. 用户手改后旧结果晚到，结果可留作候选，但不得覆盖手改。
6. 显式暂停后重启仍暂停；服务故障后按原授权恢复；等待用户不占用执行者空转。
7. 上游已收单但本地超时，优先查询而不重复生成；产物下载失败只重试接收。
8. 取消和成功同时发生，计费事实与候选保留，已取消流程不自动继续。
9. 工具返回成功但产物缺失、不可播或不符合要求，任务不能标为交付完成。
10. 反馈位置随剪辑移动，无法确定映射时不误改另一段。
11. 用户采用第二版画面与第一版音轨后，通过同步验证；撤销配音保留新的封面。
12. 不支持参考输入或所需效果时在执行前暴露能力缺口；降级不静默丢弃要求。
13. 超预算、重复失败或无进展时停止自动扩张，保留成果与可解释的下一步。
14. 成员撤权、素材权限变化和供应商配置变化后，任务恢复重新检查授权与兼容性。
15. 替换内核后，依据同一系统状态识别已完成工作与未决问题，不重复生成或扩大权限。

这些是验收场景定义，逐项实现与测试证据见 CURRENT_STATUS.md，不以清单本身作为通过声明。后续新需求先加入场景库：影响核心契约则修订基线，属于具体操作则通过工具和领域适配器扩展。
