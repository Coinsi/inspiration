# Harness 当前实现审查

审查日期：2026-10-23。对照 [设计基线](README.md)，基于本次工作区代码。多人同时实现，下面的缺口是审查时的具体代码状态；后续完成项需补充对应测试记录，不能仅把状态改成“完成”。本文件保留审查历史；当前实现、最终组合回归及部署结果集中维护在 [CURRENT_STATUS.md](CURRENT_STATUS.md)。

## 已核验的实现边界

- `harness/service.py` 持有运行、任务、尝试及有序事件，节点租约、依赖、少量工作者并行、暂停、取消、显式定向指导与旧执行者隔离均进入持久层。
- `tools/capabilities.py`、`invocation.py` 把工具执行契约与 AgentRun 分离。未知工具的副作用不会被默认当成只读；技能不能扩大权限；按需发现实际工具。
- `harness/context.py`、`media_context.py` 解析固定媒体/文档引用，区分决定、观察、推断和摘要；检查工具实际解码图片、有限视频帧和有限音频片段，并声明未覆盖内容。
- `harness/media_tools.py` 复用 GenerationJob 和原有配额，预留同一运行的生成预算，保留业务请求标识。`job_wait.py` 通过已存在的任务观察结果，未知提交不自动发起第二次付费。
- `engineering/collaboration.py` 和工程服务允许旧基线候选保存，持久化规范命令、读前提、写范围和来源；采用仍受版本保护。无关静态文档可受控重放；时间相关、同步或不能确定无冲突的操作明确拒绝自动重放。
- `conversation/production.py` 把文本和显式图片/视频生成接入同一运行类型，保留固定技能及历史媒体引用；指导后只有最新消息反映当前进度，先前消息保留快照。普通新消息不阻挡已有运行；`production` 控制字段才改变已有运行。
- 旧 AgentRun、GenerationJob 对话仍由原适配器读取；`production_harness_enabled` 可控制新消息是否走新路径。

本次本人实际运行的测试：工程及既有工程回归 54 项通过；新统一对话 12 项通过；上一轮组合回归中旧对话与旧媒体对话 18 项通过。测试使用独立 PostgreSQL schema、本地媒体与模拟内核，没有真实供应商费用。其他团队成员的测试和后续端到端结果应以主实施记录为准。

## 应补的代码，而不是继续扩大 UI

### 1. 计划契约与能力冻结

新增 `harness/plan_contracts.py`。在批准计划及委派前验证实际目录、schema、权限、调用副作用、固定引用及输出契约；返回逐任务冻结的工具版本和输入契约摘要。运行时必须比较被冻结版本，而不是把“此刻查到的版本”立即作为 expected_version。计费估价可以读取，预检禁止派发或写候选。未批准的方案可以缺预算，获批执行时必须补齐。

### 2. 用户指导与影响范围

新增持久 `feedback`/`impact` 数据：原始消息、当时工程/预览修订、实例和选区、保留约束、建议影响节点、确定性及确认状态。影响分析先产出可审核结论，只有系统验证的节点集合才进入 `steer`；定位不足应澄清。不能把所有新消息自动解释成推翻整个作品，也不能把全部修改范围选择转嫁给用户。

撤回和替代需要明确事件及 ContextFact 的 key/supersedes/withdrawn，测试“改成红衣→改成黑衣→撤回黑衣”不能靠模型历史推测决定。摘要应记录依赖事实并随其失效。

### 3. 候选采用事件回传

工程 accept/reject/rebase 应写事务事件，再由 harness 消费，带 change_id、fingerprint、固定基线、采用后工程修订、决策人和时间。只唤醒确实等待该候选的步骤；重复事件幂等；过期候选不能解锁新任务。不要在已持有工程锁时反向锁运行造成与 run→work 的死锁。既有候选预览仍独立记录。

### 4. 内核与持久协议演进

新增受控切换 API：只允许暂停且无有效执行租约的运行，比较预期修订、目标内核协议/输入模态、未完成动作支持情况，固定文本模型配置版本，记录切换事件。相同已完成任务和 GenerationJob 保持原身份。运行 JSON 应持久 schema_version/内核协议版本，恢复时通过显式迁移或阻断，不直接用新 schema 猜读旧状态。

### 5. 质量与完成定义

为技术检查、创作约束和人工审阅分别存检查记录：固定产物/工程版本、检查方法、实际覆盖范围、通过/不通过/未覆盖、证据。媒体最少增加整段解码和时长/帧率/声道/黑帧或静音等确定性检查；主观要求由带证据的观察/审阅评估。制作目标应绑定交付根及必要验收，不能由规划器把所有步骤写成 `reply` 就得到“影片已完成”。

### 6. 任务范围和资源边界

子任务应有可收窄的读写范围、工具集合和输出归属，并按父授权取交集。当前共享 run scope 只防止超过运行总授权，不能证明每个工作者只改自己的部分。将工具真实读取记录转换为工程候选的 read_preconditions，并在不可精确推导时保守固定整个作品基线。

建立全运行资源账本及 deadline，分开 token、供应商积分、渲染时长、存储/传输；支持原子预留、消耗和不确定费用占用。现有积分预留不是所有资源预算。队列还需用户/项目/供应商公平度及机器容量约束；工程/在途/审阅引用必须参与垃圾回收保护。

### 7. 具体制作能力与实际观感

高层剪辑/合成工具应产出可编辑候选，明确支持算子与仅能输出合成媒体的限制。现有图片解码、FFmpeg、原生图像/音频文档和时间线执行器可以复用；配音、配乐、动态歌词、武器局部重绘、打斗优化等仍分别需要可执行工具与能力预检。未知执行器不能被空壳注册成“已支持”。最终需要一条检索→观察→两个工作者真实并行→合成候选→预览→用户局部指导→新候选→采用的完整验收，并实际观看和试听。

## 后续补记规则

每个缺口闭合时补充实际文件、测试、固定输入及产物；付费供应商、模型观感、跨平台格式兼容等未运行的部分继续标明未验证。不能用一次模拟编排成功或前端按钮出现代替整体制作能力验收。

1. `harness/plan_contracts.py` 在计划进入执行图时检查目录、输入 schema、真实权限、副作用、固定引用和预算估价，保存每任务工具版本及契约哈希。`assert_frozen_tool` 拒绝版本变化和同版本契约漂移；工具发现也固定快照。预检不会调用生成、写候选或新建时间线。`engineering.compose` 的深层配方兼容仍明确为执行时校验，不能声称计划阶段已证明完整执行能力。`test_harness_plan_contracts.py` 8 项通过。
2. `harness/guidance.py` 将普通指导写入有序事件和持久 inbox，保存当时任务、作品修订及显式固定选区。单活跃运行中的普通对话会接续同一运行；多活跃运行必须先明确目标。只读影响任务通过结构化动作提出 discussion/question/local/global/retract，系统验证节点、原文证据和版本；不使用关键词推断整个影片重做。
3. 未决指导期间，调度和实际副作用入口阻止业务步骤新增写入或付费，已经提交的作业保留。局部改动只失效目标和依赖后继；歧义保留等待澄清状态；全局重做必须另外经过用户确认。暂停状态不会因收到指导或完成评估而自动恢复。
4. 修改决定采用原始用户消息，模型的影响解释不升级为用户授权；替代与撤回维护 supersedes/withdrawn 及摘要依赖。旧影响评估租约被新指导隔离，晚到结果不会覆盖新意见。已采用工程版本变化后，原影响分析不能直接应用，需重新评估。
5. `conversation/production.py` 支持明确 guidance/confirm_guidance 控制，同一运行只有最新消息为实时进度。旧消息保留快照；待确认范围作为 metadata 返回，避免将全局确认混作普通问答。新增 HTTP 测试包含普通续聊、多运行消歧、全局确认、幂等和生成后真实本地技术验收。

本轮实际验证：`test_harness_guidance.py` 9 项与 `test_harness_conversation.py` 14 项共同运行，23 项通过（53.05 秒）；这些测试使用真实隔离数据库、真实控制/API/调度路径和模拟语义内核，没有向付费模型发送请求。真实模型对模糊意见的定位准确率、选择性修改后的观感仍未验证。工程时间映射、用户明确取消上游作业、供应商实际账单与进程重启故障窗口等，仍须逐项按基线验收。

随后增加真实状态链“红衣→替代为黑衣→撤回黑衣”，验证红衣与相关摘要不会复活；指导专用测试再次运行 10 项全部通过（33.53 秒）。

## 2026-10-23 补记：固定反馈定位与选择性引用变更

新增 `harness/feedback_tools.py`，提供两个独立领域工具，无需 Agent 内核也可通过同一工具调用契约使用：

- `engineering.feedback` 读取固定文档和修订，支持原生图层、音频/合成的有理数时间映射，以及剪辑的片段、音轨和叠加画面。转场按真实渲染的重叠时间处理；循环、倒放、停帧和多实例返回明确坐标及歧义，不擅自选第一个。嵌套实例路径逐级映射时间点，并同时保留顶层与实际到达文档身份。返回实际读取的修订前提，供系统跟踪依赖。
- `engineering.selective_edit` 从固定候选选择原生实例的 source/mask 引用替换，或撤销已经采用的这类替换，产出新的待审候选。当前被选引用必须仍符合预期，否则拒绝覆盖；未选实例和当前其他参数保持原样。采用仍由工程审阅完成，工具不会自动采用或恢复整个工程。

`test_harness_feedback.py` 6 项领域/API/实际工具调用测试通过（11.99 秒）。验证内容包括旧版本不随新时间线漂移、循环倒放区间、转场重叠、静态图无时间轴、嵌套路径、选择单个候选引用、撤销时保留另一实例手改，以及选中位置被另改后的冲突保护。未调用付费模型。

明确边界：反馈定位不自动将旧坐标迁移到新剪辑；嵌套路径目前只映射时间点，直接实例可映射区间。选择性变更目前仅覆盖直接原生输出的 source/mask 替换，不覆盖新增/删除实例、任意参数撤销、剪辑重新排序或跨层同步整合。上述复杂操作须继续通过明确工程候选和原有同步审阅，不能由这个工具默认放宽。

## 2026-10-23 补记：跨任务边界故障审计

新增 `test_harness_audit.py`，用真实隔离数据库和运行时复现后修复了 `service.control` 的三处转向缺陷：

1. 多个父节点的子项同时失效时，旧实现将同一个替代任务挂到多个父节点，实际 `parent_id` 只剩最后一个。现在按受影响边界分别替代，父节点保留原来的子项顺序，跨边界依赖指向各自的新任务。
2. 局部任务原来按根任务重新创建，可能把已收窄的创作对象和工具范围扩展成整个运行授权。现在替代任务保留原范围、工具白名单、已读取的工具契约、质量要求和实际读前提；父子同时选中只替代父边界一次。
3. 修改深层子项时，依赖其祖先汇总结果的下游成片原来可能仍标记成功。现在祖先重新汇总，旧决定和租约被隔离，其结果的消费者重新规划；未受影响的兄弟成果保留。

同一审计还验证了两段对话关联同一作品时，晚到候选仍可保存，但不能覆盖先采用的版本；暂停和恢复不能重提未知付费请求；工具版本或同版本输入 schema 漂移会在真实运行时阻止 handler 执行。

最终 `test_harness_audit.py` 7 项与 `test_harness_runtime.py`、`test_harness_guidance.py` 联合运行，42 项通过（52.44 秒）。不包含付费模型调用或新的媒体供应商验收。

仍需保持保守边界：同一步骤先后读取同一文档的不同修订时，系统保留两条读前提，不会自动以新读覆盖旧依赖。需要有意改变计算基线的场景，应通过明确的新计算/重新评估协议处理；不能通过简单删除旧前提来宣称无冲突。

## 2026-10-23 补记：持久资源预留与输出硬上限

`harness/resources.py` 现在对模型 token、媒体输出存储和媒体传输保留持久预留；缺失或无效用量不当作零消耗。实际用量可回收差额，也可如实记录超过估计的用量并阻止后续副作用。并行步骤在同一运行行锁内预留，重启不会释放未知占用。限额调整只允许已列明的资源字段，不提高生成权限或积分授权，显式暂停保持不变。

新 harness 生成任务将 `count × 256 MiB` 写入持久输出限制，本地处理使用配方预检的上限，工程预览使用 `512 MiB`。`generation/jobs.py` 在任何 CAS 写入前检查全部输出总字节数，超过上限时整批拒绝；外部下载按剩余额度限制读取。普通旧任务没有该标记时保持原行为。资源预算不再只是界面上的计数。

`test_harness_resource_ledger.py` 与媒体生成、确定性处理、工程预览和原资源/审阅测试联合运行，53 项通过（134.76 秒）。包含真实数据库重启读取、4 个并发 worker 的共享预留、实际 Blob 大小结算、旧 kernel 与带 usage envelope 的兼容，以及 bytes/临时文件两类超限输出零 CAS 写入。测试未调用付费接口。

媒体观察额外预留实际发送的媒体 JSON 负载字节（含 base64 开销）；这是应用层媒体传输计量，并非云存储、CDN 或供应商的真实计费流量。模型 token 在供应商返回有效 usage 前仍是保守预留，不声称提前精确计费。

追加媒体观察传输上限和无效持久 cap 提前阻断之后，资源账本专用测试再次运行，21 项全部通过（42.41 秒）。
