# 工程设计校验报告

日期：2026 年 10 月 18 日。范围为工程设计草案 0.1 的结构、契约与反例检查；修订结果为 0.2。没有实现或运行媒体引擎，没有调用生成模型，没有验证实际画面、声音和生产环境。

本报告保留第二轮历史结论；下方六类待细化项的后续决定及边界见 [0.3 校验记录](DESIGN_REVIEW_03.md)。

## 结论

初版的 30 个探针不足以证明设计完整。第二轮实际构造了五类非法输入，初版探针均未拒绝；同时检查到输出束、锚点映射、读集版本和时间失效等需要明确的设计规则。

本轮将其补入契约和设计探针，合计 64 项检查通过。结果支持继续细化工程设计，不能据此冻结完整格式或报告特效、配音、图像修改等功能可用。

## 实际复现的缺口

以下是对初版 `validate` 或能力预检的实测，不是线上产品漏洞报告。

| 编号 | 反例 | 初版结果 | 修订与证据 |
| --- | --- | --- | --- |
| F01 | 将 glow 的输入改成音频，并把 accepts 也改成 audio | 结构校验接受 | 不能信任客户端端口声明；与受信任定义比对。T34、T57 |
| F02 | 4 秒歌词合成的第二句结束时间写成 9 秒 | 结构校验接受 | cue 唯一 ID、有效时间与非空正文。T38、T39 |
| F03 | 特效强度写 NaN | 结构校验接受 | 有限数值、单位、模式、范围与参数名约束。T40 至 T42、T59 |
| F04 | 海报 kind 改成未知类型，不设置 operator | 预检返回空缺失集合 | 同时检查 kind、schema_version 和实现；未知数据不解释。T35 至 T37、T60 至 T63 |
| F05 | 将第二个视频移到同轨道第一段内部 | 结构校验接受，契约无明确默认 | 轨道必须声明拒绝、叠放或混音；转场另行定义。T43 |

F01、F02、F03、F04 部分要求在初版文字里已经存在，但没有落实到可检查约束。不能把这类探针遗漏包装成已经验证的设计能力。0.2 增补的是测试夹具里的契约检查，生产端仍需正式实现。

## 设计推演补齐的规则

| 编号 | 问题 | 决定 | 证据 |
| --- | --- | --- | --- |
| D01 | 初版输出根只有一个端口，带声音成片没有明确封装 | 一个输出束锁定单一根修订及多路流；独立流不能各自跟随版本 | 格式 2 样例；T31 至 T33、T58 |
| D02 | “跟随片段”无法解释移动、变速、停帧 | absolute/local/source 分开；源内容更新复核；停帧逆映射有歧义 | T45 至 T48 |
| D03 | 同一内容值改回原值，旧任务会不会误通过 | 比较修订令牌，不只比较值；恢复也是新修订 | T52 |
| D04 | 特效读取窗口和失效窗口方向不同 | 输入变化范围反向使用读取前后窗口；有状态变化保守传播到后面 | T49 至 T51 |
| D05 | 所有依赖变化是否清掉历史缓存 | 固定版本不变；反向依赖是升级影响分析，新提交用新键 | T64 验证旧依赖闭包保留；缓存实现未测试 |
| D06 | 参数曲线和字幕的结束边界是否相同 | 曲线控制点可位于 duration；媒体采样和字幕区间仍左闭右开 | T30、T38、T42 |
| D07 | 视频停帧规则直接用于声音 | 音频 rate=0 要求明确处理，不作默认视频式停帧 | T44 |

## 校验方法与结果

执行命令：

```powershell
python -m unittest discover -s docs/architecture/editable-project -p "verify*.py" -v
```

结果：64 tests，OK。T01 至 T30 为首轮基础探针，T31 至 T64 为本轮增补。测试包含正例、故意破坏的引用/类型/范围、局部修改后的旧版本保持，以及纯状态模型中的提交顺序枚举。

T53 枚举三个互不依赖修改的全部六种提交顺序，检查无关新状态保留。T54 枚举三个冲突写入的全部六种顺序，检查旧修订的后续写入被拒绝。它们没有模拟真实数据库锁、进程崩溃或网络分区，因此不能称为数据库并发测试。

T49 至 T51 验证单一时间坐标下的失效公式；没有验证嵌套变速、VFR、粒子求解或真实帧缓存。T45 至 T48 验证单实例常速锚点；没有完整实现跨文档时间求解。

未知类型保留的检查只针对规范 envelope 和 JSON 载荷，不代表任何第三方格式可以无损导入。缺少操作实现会阻止样例预检，但测试注册表中的算子名称也不代表已有可执行代码。

## 设计阶段还未关闭的事项

以下保持未关闭，不以测试数量掩盖。它们有明确方向，但尚无完整 schema 或算法验证：

1. 跨嵌套、分段变速、循环播放的时间映射与 occurrence 身份，需要补独立的数据契约和模型测试。
2. 同步组、波纹编辑、滑移、转场余量和受保护轨道的命令语义，需要给出完整前后样例。
3. 蒙版、坐标变换、色彩、Alpha、音频声道和延迟补偿，需要制定具体类型定义；端口只匹配 video/audio 远远不够。
4. 多路径同时升级、跨输出方案部分采用、反向撤销和合并审阅，需要完整变更集模型；目前没有证明任意合并安全。
5. 格式 1 到 2 的输出选择迁移，以及后续未知字段往返，需要正式兼容测试，当前只有拒绝和不透明保留规则。
6. 保留根、回收、权限撤销、导入身份重映射和运行幂等，需要独立状态模型检查，不能从引用闭包测试推导为已完成。

因此，本轮可以确认初版已检查到的矛盾和探针漏检得到修正，不能确认“所有后续功能都已通过设计验证”。后续仍以这些未关闭项继续设计校验；渲染与生成执行验证属于另一个阶段。
