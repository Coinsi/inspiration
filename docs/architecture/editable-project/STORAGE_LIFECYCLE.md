# 工程媒体生命周期

物理回收默认关闭（storage_gc_enabled=false）。不得只在删除进程启用：所有 API 和工作进程必须先使用支持读取保护的版本并同时启用。当前没有自动扫描或后台清空用户存储的任务。

## 持久状态与身份

- Blob.hash 是内容身份；storage_uri 是独立的物理对象身份。修复和重新上传被回收的内容使用新 UUID 路径，避免迟到的删除响应误删新文件。
- BlobDeletion 保存捕获的旧 URI，状态为 marked、deleting、deleted 或 canceled；记录不依赖 Blob 外键，也不作为素材保留理由。
- mark 检查全库外键和 JSON 引用，默认保留 24 小时。执行前再次检查；新增引用或物理身份变化会取消该次删除。
- 删除先提交 deleting 状态，再执行精确对象删除。删除成功但响应丢失时，重试同一个操作，仍只针对原 URI。

## 竞争保护

- CAS 写入持有内容哈希的事务锁。回收尝试获取同一锁，正在上传时让步。
- 读取持有 PostgreSQL 共享事务屏障；回收尝试排他屏障，不等待正在进行的读取。嵌套读取复用连接。
- 提交删除状态前锁定业务表并重查引用。数据库触发器拒绝新增指向正在删除物理对象的引用，覆盖普通字段、JSON 值及 JSON 对象键。
- 回收检查当前表与 ORM 表集合、触发器覆盖是否一致。新增业务表未部署保护时拒绝物理回收。
- 本地删除只允许配置 CAS 根目录内、匹配内容哈希的单个文件；对象存储只允许配置桶内匹配的对象键。没有递归删除。

## 运维边界

当前入口为 storage.garbage_collection.mark / execute，需显式启用；没有向普通前端或 Agent 暴露物理删除。生命周期后台扫描、运营保留策略、全局屏障替换为细粒度租约均未实现。该机制不等同于对已有缺失文件的自动修复。

测试使用隔离 PostgreSQL schema 和临时文件；不删除实际项目媒体。验收涵盖读取/上传竞争、保留期、新引用取消、外键及未知 JSON 扩展引用、丢失删除回执、重复执行、重新上传、未安装保护和越界路径。
