当前实现以[底座交付范围](FOUNDATION_ACCEPTANCE.md)和[工程底座验收状态](CURRENT_STATUS.md)为入口；下文是目标设计，不是已完成功能列表。

媒体保留、回收状态与部署边界见[工程媒体生命周期](STORAGE_LIFECYCLE.md)。
归档恢复的当前实现和未完成事项见[工程归档传输](ARCHIVE_TRANSFERS.md)。

状态：设计草案 0.3，2026 年 10 月 18 日。本文定义目标结构，不代表生产功能已经实现。当前代码对照基于 `d7ba587`。

工程用于长期保存、修改和交付图片、音频、动画与影片。用户界面和 Agent 通过相同的工程操作服务工作；对话、模型供应商和执行任务都不是工程的存续条件。平台内的合成与特效是本设计的一部分，不以安装 Adobe 软件为前提。

代码落地进度单独记录在[实施记录](IMPLEMENTATION.md)。第一批仅包含作品、资源清单和审阅提交，不代表以下全部目标能力已经实现。

本轮交付包括 [数据与操作契约](CONTRACTS.md)、[功能覆盖与验收](SCENARIOS.md)、[具体工程样例](example.json) 和 [设计校验程序](verify_design.py)。校验程序只验证选定的数据与算法规则，不渲染画面，也不证明视觉质量、数据库并发或生产部署已经通过。

[第二轮校验报告](DESIGN_REVIEW.md)保留 0.2 的发现。[细化契约](DETAILED_CONTRACTS.md)与[第三轮校验记录](DESIGN_REVIEW_03.md)补齐时间/同步、编辑命令、媒体类型、多对象采用、迁移和运行存续规则。三组程序合计 105 项设计检查；不代表完整 schema 或媒体执行通过。输出样例保持格式 2，明确共同锁定画面与声音；细化契约中的扩展未全部加入该最小样例。

## 设计结论

采用版本化资源、可组合的编辑文档、显式依赖及原子变更集。工程同时拥有剪辑结构和合成计算结构；原始素材、某次使用、处理过程、采用决定及渲染结果分别保存。

不把所有业务塞进一张时间线，不把任意业务 JSON 当作已经实现的能力。扩展类型需要配套校验器、操作接口和执行能力。允许未知类型原样保留，但不得静默省略它们后输出看似完整的成片。

新增能力可以扩展类型和操作版本；已有格式不得被原地改义。兼容、迁移和渲染差异必须有明确处理。不能保证所有未来需求都无需升级格式，但应避免新增能力导致原有作品丢失、无法解释或必须全部重建。

## 工程边界

| 对象 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 项目 Project | 成员、权限、素材组织、多个作品 | 不等于一条时间线 |
| 作品 Work | 创作身份、名称、多个工程分支和输出 | 不强制绑定剧本或对话 |
| 工程提交 Commit | 固定一组根文档、要求、采用决定和依赖版本 | 不保存运行中的任务进度 |
| 编辑文档 Document | 图像、合成、剪辑、音频、叙事等结构 | 不直接承担供应商请求生命周期 |
| 素材资源 Resource | 源内容、辅助数据及不可变版本 | 不决定所有使用位置是否采用 |
| 使用实例 Instance | 某次使用的范围、位置、变换和覆盖参数 | 不修改源文件 |
| 变更集 ChangeSet | 基于明确前提提出一组可检查修改 | 不绕过权限或自动覆盖新状态 |
| 任务 Run | 执行、进度、取消、重试、计费与恢复 | 不是作品唯一事实来源 |
| 渲染产物 Artifact | 固定输入和环境生成的预览、导出或代理 | 不替代可编辑工程 |

单独生成图片可以先形成会话候选和资源；没有编辑需求时不强迫用户建立复杂工程。需要继续编辑、组合或采用时，由系统建立最小工程，仍使用相同资源身份。工程复杂度按需增长，不暴露为一排必须填写的表单。

## 不可破坏的规则

1. 生产引用使用稳定身份和固定版本，不依赖文件名、临时链接、供应商任务号或本机路径。
2. 已发布内容版本不可原地覆盖；名称、目录、收藏和运行状态不与不可变内容混为一体。
3. 图片局部修改、时间线裁剪、生成新视频分别属于不同操作，不能用统一的“覆盖文件”实现。
4. 对象可被多处引用，每处使用有自己的实例；源更新不自动改变所有已采用实例。
5. 任一任务固定输入快照；结果完成不等于采用，也不能直接覆盖任务启动后用户的新修改。
6. 输出提交必须解析到完整的依赖版本；保存、可编辑、可渲染、可交付是不同状态。
7. 内容依赖与制作计算在同一快照内不得形成循环；故事关系和反馈关系允许有循环，不能拿来当渲染图执行。
8. 变更涉及多个对象时整体校验、整体提交；同样的修改规则同时用于 UI、工具和 Agent。
9. 自动观察、创作要求、用户认可分别存储；生成错误不能变成默认故事设定。
10. 缓存可重建，已采用的随机生成结果是受保护源内容，不能按普通缓存清理。
11. 读取或命中内容哈希不产生权限；共享缓存和素材检索必须在租户授权范围内工作。
12. 已冻结分支或导出不会因默认模型、效果实现、预设或外部内容更新而静默改变。

## 资源和引用

资源分成语义身份与内容版本。一个资源身份可以有多个版本，每个版本关联一个或多个物理内容，例如视频主文件、帧时间索引、透明通道或图像序列清单。内容使用哈希验证，位置由存储解析器查找。

资源类型除图片、视频、音频外，还包括蒙版、深度、矢量、字体、LUT、运动轨迹、字幕对齐数据、三维网格和模拟缓存。类型采用命名空间扩展，不要求导入所有媒体时预先产生全部辅助数据。

原始数据有技术描述：媒体流选择、时长、尺寸、方向、像素宽高比、色彩与 Alpha、帧率或可变帧时间索引、音频采样率与声道。转写、物体识别和检索向量是依赖源版本的分析产物，记录分析器版本、范围、置信度和人工纠正记录。素材改名不触发重新识别；重绘不能无条件继承旧识别结果。

### 引用类别

| 类别 | 示例 | 更新规则 |
| --- | --- | --- |
| 内容引用 | 实例引用素材版本、序列引用子合成 | 固定版本；升级创建变更集 |
| 计算输入 | 发光输入图像和蒙版、混音输入声音 | 类型检查、参与渲染依赖与缓存 |
| 创作关联 | 镜头表现某剧情、角色使用某武器 | 影响分析后复核，不直接重算全部 |
| 来源关系 | 候选从旧图和修改要求产生 | 只追加记录，不作为新图渲染输入 |
| 临时探索引用 | 检索命中的未采用素材 | 可过期；采用前重新验证权限与存在性 |

工程对资源的采用会建立保留记录。跨项目复用保留独立的逻辑归属和权限，即使物理内容去重。完整导出需要检查依赖闭包及可导出的权限；不能仅因工程引用了某资源就将其公开。

成片输出是一个绑定单一根修订的输出束，包含显式的画面、声音及规格；静帧输出只有图片流，静音视频必须明确声明静音规格。不能让画面和声音各自跟随不同的“最新时间线”。不同语言或输出版本建立各自的根，分别冻结。

## 编辑文档和合成计算

| 类型 | 主要结构 | 输出 |
| --- | --- | --- |
| 叙事文档 narrative | 情节、角色、事件、对白、场景、要求 | 结构化创作数据 |
| 图像文档 image | 画布、图层、文字、蒙版、效果、混合方式 | 静态画面 |
| 合成文档 composition | 图层、实例、动画、跟踪、嵌套、合成图 | 画面序列，可含声音 |
| 剪辑序列 sequence | 轨道、片段、转场、同步组、标记 | 画面序列与混音 |
| 音频文档 audio | 片段、轨道、效果、总线、声道映射 | 声音 |
| 扩展文档 extension | 按类型定义的空间场景或其他专业结构 | 经声明的端口类型 |

没有剧本也可以创建图像或声音。镜头是创作对象，不等于物理视频；一个镜头可以引用合成，一个素材可以服务多个镜头，一个序列片段也可以不关联镜头。剧情、镜头和片段之间允许多对多关联。

### 文档内部

图层负责可见性、变换、混合和顺序；轨道负责时间组织与声音路由；计算节点负责带类型的输入输出。节点内部的执行图不等于界面中的自由画布，也不等于 Agent 的执行计划。

复杂文档可以拆成对象修订以局部读取和提交，不要求一个图层一张数据库表。第一版允许文档作为冲突粒度；热点文档以后可将稳定组件身份拆分，导出语义不变。

合成发布有名称的输入和输出端口，端口类型例如静态图像、随时间变化的图像、音频、蒙版、变换轨迹、几何。尺寸、时间基准、色彩等附加约束同样要校验。静态图片变成一段视频、音视频变速和色彩转换必须是显式适配，不依赖某个渲染器猜测。

复用子合成时允许指定公开参数覆盖。仅该实例覆盖，不修改共享模板。需要改变未公开的内部结构时创建分支或新修订，并只更新选定的引用路径。模板更新不会自动升级已发布实例。

### 效果和参数

每种效果声明参数类型、单位、有效范围、默认值、是否可动画、是否允许绑定、插值规则和输入输出类型。参数来源只允许一个确定来源：常量、动画曲线或绑定；覆盖共享默认值时记录实际生效来源。

关键帧有稳定身份，时间使用所在文档的时间坐标。步进、线性和曲线插值明确区分；文字、枚举和数值不能共用含混插值。坐标同时声明原点、方向、单位和所属空间；蒙版、跟踪与转场在正确空间里组合。

表达式只允许受限、版本化的求值能力，不在工程中执行任意网络、文件或系统命令。绑定图需要循环检测。三维场景、灯光、摄像机、深度排序和粒子属于扩展能力，不能声称二维图层已覆盖全部三维语义。

### 有状态计算

单帧效果、邻域帧效果、全段分析和有状态模拟分别声明依赖范围。模拟记录初始化参数、随机种子、实现版本、预滚范围及检查点；更改前面的状态可能使后面整段失效。反向播放和随机跳转可能需要从检查点重算。未知影响范围按扩大范围或整段重算处理。

普通引用图不允许循环；确需反馈的模拟由明确的有状态算子封装，其前一时刻状态属于算子协议，不开放任意零延迟循环。

## 时间和同步

时间值使用有理数 `numerator / denominator` 秒。媒体同时保存其原始采样时间基准；内部不统一量化成毫秒。整数以字符串序列化以避免浏览器大整数精度丢失。时间区间统一左闭右开；端点、越界及舍入在编译到帧或采样时明确处理。

四种坐标分别保存：源媒体时间、实例局部时间、父合成或序列时间、故事中的时间。故事时间不参与渲染求值。可变帧率通过帧时间索引解码，不用平均帧率推算任意帧。

实例包含父级放置位置、局部持续时间和源时间映射。映射可分段表达常速、变速、倒放、停帧；音频变速需声明保持音高与否。越界是报错、留空、循环还是保持边缘必须显式声明。

字幕和特效可锚定片段、对白、动作标记或绝对成片时间。锚点依赖稳定对象身份，同时记录评估时采用的版本。目标移动时按跟随策略迁移；目标删除、重生成或非线性变速导致关联不可靠时，返回需修复状态。

剪切、波纹编辑、滑移、滚动、连接、分离和转场均为明确命令，带轨道范围、锁定规则和同步组策略。转场说明消耗片段区间还是使用额外素材余量，不能由不同播放器采用不同解释。

轨道必须明确重叠处理方式：拒绝、按顺序叠放、混音，或由明确转场操作消解。视频叠放按稳定轨道/片段顺序确定；声音不能沿用图层覆盖语义。停帧视频可以保持一个有效采样点，声音 rate=0 必须使用明确的静音或其他处理算子。

音频支持剪辑级增益、自动化曲线、效果链、总线、声道布局和延迟补偿。同步组可以把口型、配音和字幕联系起来，但不强制将跨镜头音乐绑定到单个视频。分离出来的人声与伴奏是带质量限制的新资源，不能假设原始混音天然拥有独立音轨。

## 精确修改和创作判断

编辑目标由输出入口、嵌套实例路径、对象身份、时间范围及可选空间选区组成。同一源文件被使用两次时，这个地址区分具体使用位置；针对源内容的修改使用另一种明确作用域。

创作要求包含目标、参考用途、期望变化、保留要求、作用范围和验收方式。用户说“眼神坚定一些”时，修改目标可绑定人物区域，保留要求包括脸型、衣服和构图，但工具是否做到仍需检查。

实际观察绑定精确版本和范围，记录来源、方法和置信度；人工反馈可以确认或纠正。采用决定绑定具体位置、候选修订和输出规格。低分辨率预览的通过，不自动代表高清材质细节或最终声音通过。

“打斗不精彩”可能产生剪辑调整，也可能产生新的动作设计和生成任务。工程只负责表达场景目标、镜头联系、候选方案和反馈，不把主观质量等价成一个技术分数。用户转向后先评估影响范围；可复用旧素材不因剧本变更而删除。

## 版本与协作

稳定对象身份不等于版本。修订是不可变内容，分支指向提交，提交引用具体根修订。提交可以采用持久化目录树，避免每次保存复制全量对象。渲染以某次提交及依赖闭包为边界，不读取执行过程中变化的“最新版本”。

引用固定修订意味着修改子对象后，要在变更集中创建受影响父引用的新修订，直到选定输出根。系统完成这一步，用户和 Agent 不必逐层改 ID。只改一个实例时只重建该引用路径，不升级其他路径。

并发修改通过读集、写集和不变量校验处理。读集包括时间位置、布局、约束和权限等实际前提，而非只记录写入字段。长任务不持有数据库锁。提交时短事务检查、更新分支指针并写入待派发事件。

读前提固定修订令牌而非仅比较值。内容先改成 B 再恢复为 A 仍是新修订，基于旧 A 的任务不能因文字相同就自动视作有效。需要复用时重新验证当前输入及用户意图，构造新的提交前提。

用户直接操作按其明确动作保存；Agent 修改已有采用内容默认形成候选。整个候选审批须绑定变更内容和前提摘要；重新合并导致含义改变时原批准失效。全局回滚、局部撤销和采用旧候选分别是不同命令。

候选保存不要求当前分支仍与任务启动时相同；采用要求重新验证依赖。晚到结果可以归档为候选，但不得直接写当前采用指针。冲突未解决时用户仍可查看和比较候选。

## 操作服务与工具

工程操作服务提供读取、合法操作查询、变更构造、影响预览、校验、提交、比较、恢复和渲染请求。UI 和制作工具使用同一服务，Agent 内核通过工具层调用。

用户表达意图；主 Agent 按需发现制作能力；专业工具组合领域命令；执行组件完成处理。不能把每个图层属性包装成默认对话工具，也不能以一个无结构的万能执行接口绕过工程规则。

检索、生成、转码可以独立服务于其他场景。它们参与作品时返回标准资源或变更候选，通过工程服务登记。工具不能私有保存另一套最终镜头、最终声音或采用状态。

## 执行与渲染

工程描述、渲染编译计划和队列任务分开。编译器解析固定引用，检查资源、端口、时间、参数、执行能力和输出设置，形成可执行计划。第一版可以用现有服务扩展，不要求立即拆分微服务。

预览和正式导出共享操作语义；预览配置允许低分辨率或声明过的近似，并将差异随结果返回。最终输出在必须能力缺失时失败，不能省略不支持效果。交付产物记录工程提交、输出入口、规格、执行环境指纹和校验摘要。

缓存键依据输入内容、实际参数、时间范围、效果和执行版本、字体等依赖及输出配置。随机生成素材固定结果，不因相同提示词而假定能复现。硬件或算法差异可能影响像素，不承诺仅凭工程描述即可逐像素重现。

新候选不会使旧版本缓存失效。影响分析计算的是引用升级后的变化，新提交使用新计算键；旧提交仍可复用旧结果。任何基于“最新资源”直接清空已固定版本的处理，都不符合本设计。

运行状态至少区分排队、执行、等待外部服务、取消请求、已完成、失败和外部结果未知。请求幂等键、外部任务号、回执与费用归运行系统；供应商不支持查询时，不能把未知状态当作安全重试。结果发布和工程采用是独立步骤。

## 存储与工程包

数据库保存对象身份、修订索引、提交、分支、关系索引、保留记录和审计；对象存储保存原始媒体、大型文档载荷及派生产物。小载荷可用 JSONB，但类型适配器必须校验。关系索引从规范引用提取，可重建，不与载荷形成两个互相矛盾的事实来源。

导出包包括格式版本、能力清单、输出根、对象修订、依赖清单、校验和与可选媒体。轻包允许外部依赖但必须声明；完整包须检查选定输出的依赖闭包。历史、候选和未使用素材是否包含由导出配置决定，不承诺完整包自动包含全部历史。

导入先校验路径、大小、哈希、结构和权限，再写临时空间，最后发布。不同来源身份冲突时建立 ID 映射并重写引用，不覆盖现有对象。导出的身份不携带原租户访问权；导入创建新的归属和保留来源信息。

保留根包括采用提交、保留的历史与候选、正在执行的输入租约和合法保留记录。清理采用标记与延迟回收，正式删除与新引用/租约发布必须通过 deleting 状态和代次协调，不能只做一次无锁复查；删除素材目录项不等于删除物理内容。权限变化、强制删除或缺失依赖保留可诊断占位，不伪装成空白成功。

## 扩展与兼容

扩展清单声明类型及结构版本、参数定义、读写与校验适配器、输入输出、执行器要求、预览支持、依赖提取、时间影响、迁移和安全限制。能力是否可运行由执行环境预检决定，不能仅依赖扩展自报支持。

未知必需类型可以保留和展示历史结果，但受影响编辑及渲染禁用。旧客户端提交局部命令，服务端保留未修改扩展；不接受客户端将不了解的数据作为完整新文档覆盖。迁移生成新版本，保留旧提交与迁移报告。

外部专业格式可作为扩展资源保存，导入导出提供能力损失报告；这不替代平台原生合成能力，也不默认承诺无损兼容所有软件。

## 与现有系统的衔接

| 当前位置 | 已有基础 | 目标调整 |
| --- | --- | --- |
| `backend/app/models/work.py` | 作品身份 | 解除必须关联单个剧本，关联工程分支和输出 |
| `backend/app/models/library.py` | 不可变素材版本、跨项目复用 | 统一资源引用及保留策略，加入辅助资源适配 |
| `backend/app/models/generation.py` | 固定生成输入、供应商任务与结果 | 生成结果适配为资源；任务不是编辑引用的唯一入口 |
| `backend/app/models/timeline.py` | 剪辑、音轨、字幕、视觉层和历史 | 稳定实例、通用来源、文档引用、精确时间 |
| `backend/app/modules/timeline/schemas.py` | 现有编辑输入校验 | 逐步解除镜头和生成记录强绑定，保留旧接口适配 |
| `backend/app/modules/timeline/editing.py` | 乐观版本检查、历史恢复、媒体校验 | 统一变更服务；避免大工程所有修改长期串行化 |
| `backend/app/models/versioning.py` | 修订、关系和基线 | 对接提交和内容依赖；迁移期禁止两套独立采用事实 |
| `backend/app/models/evidence.py` | 身份与经过审阅的观察 | 扩展目标范围，关联要求与采用决定 |
| `backend/app/models/canvas.py` | 文档快照与运行批次 | 保留工作流用途，不把工作流图当成合成图 |
| `backend/app/modules/tools/registry.py` | 类型化工具与共享调用上下文 | 经工程操作服务执行，目录按需发现 |

当前时间线 DTO 有 100 个主片段、最多 3 条视觉轨道等约束，并使用毫秒和生成记录来源。这些是现实现边界，不进入新格式的固有限制；服务端仍需可配置资源限额，不能把去除格式限制理解为无资源上限。

### 迁移步骤

1. 先固定引用、时间、变更和扩展规则，建立旧数据读取适配器及工程预检。
2. 影子转换现有时间线、音轨、字幕和视觉层，保留旧 ID 映射，不修改线上采用结果。无法确定来源的旧数据报告缺口，禁止猜测。
3. 对同一固定数据分别走旧、新渲染路径，比较时长、片段边界、字幕、画面布局和声音；允许差异必须逐项记录。
4. 按作品切换写入所有权。切换后新工程服务是唯一写入口，旧页面通过适配层调用；不让两套模型自由双写。
5. 加入原生图层、效果、动画和合成执行能力，再扩展跟踪、粒子等算子。工具和 Agent 随能力验收逐项开放。

每一步保留回退指针。旧渲染器不能表达新操作时，只能回退到切换前快照并保留新分支，不能声称旧系统可以继续无损编辑所有新功能。

## 定稿与实施门槛

0.3 草案给出结构、细化契约及失败规则。设计校验与场景推演能发现结构冲突，不能替代实际效果验证。实施关口见[第三轮校验记录](DESIGN_REVIEW_03.md)：正式 schema、持久化协议、编辑/最小媒体执行、旧项目迁移、工具与 Agent 闭环分别验收。跨文档时间与扩展已有规则及选定探针，完整求解器和兼容矩阵尚未实现；渲染器选择必须以动态歌词、剑光遮挡、对白混音的真实样片验证。

未决实现选择包括浏览器预览与服务端渲染组件、色彩执行库、音频处理器、跟踪和生成模型、模拟实现，以及大规模协作存储策略。它们必须遵守本文契约；遇到无法实现的语义，需要修订设计并记录兼容策略，不能仅标记“已接入”。
