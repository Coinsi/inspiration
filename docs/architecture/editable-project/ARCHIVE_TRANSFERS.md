# 工程归档传输与后台任务边界

## 当前已实现

`archives.build` 支持服务端独占的 `checkpoint_dir`，以及 `canceled` 和 `progress` 回调。现有同步接口保持兼容并复用持久任务、空间预留与下载读取保护；传入暂存目录的执行器可恢复媒体读取，不需要从头下载已校验的素材。

1. 在暂存目录持有操作系统文件锁，重复进程无法进入；进程退出或崩溃后锁释放。暂存目录必须是服务端分配的私有目录，不接收用户路径。跨主机必须使用具备可靠文件锁语义的共享存储，否则不得共享此目录执行任务。
2. 保存固定工程包清单。再次执行必须匹配完全相同的清单；作品后续修改不能悄悄改变正在导出的版本。
3. 每个媒体用独立 `.partial` 文件暂存，逐块落盘。恢复从已落盘长度发起 Range 读取，并重新计算已存前缀的哈希。
4. 素材完整哈希与清单匹配后才提升为完整暂存文件。损坏的部分文件不会发布，重试重新读取；已经完成的文件也需重新校验，不能仅凭存在就信任。
5. ZIP 写入临时文件，取消或失败清理该 ZIP；已校验媒体保留用于重试。最终 ZIP 必须完整关闭后才可发布。

进度含 `phase`（staging / packing）、`completed_bytes` 和 `total_bytes`，不同阶段不得混算为一个单调百分比。完成取消检查每块执行，内存有界；大文件不会一次载入内存。

归档校验与恢复同样接受取消回调。校验按块中断，取消保留原异常类型，不包装成归档损坏；恢复在候选发布前再次检查。调用者仍负责事务回滚，取消不会删除用户提供的原归档。

## 尚未实现，不应在页面宣称已经支持

- 下载 API 支持 Range，但浏览器下载中断后的自动续传体验未实现。
- 跨主机任务调度和存储路由；当前要求一个持久暂存卷，不宣称已经支持多节点任意扩容。

## 已接通后台导出

0045 持久化 EngineeringArchiveJob 保存固定作品修订和 snapshot。API 提交只创建任务，后台扫描 pending/running；PostgreSQL 事务咨询锁让同一任务只能由一个执行器持有。进程崩溃后锁释放，后续扫描继续固定输入。状态和进度独立提交，不阻塞取消；发布结果前复查任务状态与项目权限。失去锁连接的执行器不能提交失败状态覆盖新执行器。

作品 → 工程内容 → 保存与恢复工程显示任务列表、进度、取消、重试及下载。刷新后任务仍在数据库，完整归档下载支持 Range；结果文件丢失可重新准备。任务创建使用请求键幂等，操作由任务创建者管理，列表和下载检查作品范围及项目权限。

当前 API 进程内独立后台线程执行归档，关闭时取消本轮并保留 pending；不依赖浏览器长请求。文件暂存及结果位于 fs_storage_dir/_engineering_exports，部署需持久卷。容量预留和过期清理见下文；尚无跨主机路由，不应将其宣称为任意规模云端迁移已经完成。

## 测试证据

0046 增加导入会话及持久上传偏移。页面按 8 MiB 分片上传，可刷新后选择同名同大小的原文件续传，并复核已上传前缀。服务端逐片校验位置；重复片必须逐字节相同；文件已写入但事务未提交的尾部在重试时截断。完整上传才进入后台，ZIP 内容及每个媒体哈希仍做完整校验。

后台导入与候选发布共享一次数据库提交；用户取消会回滚候选，自动恢复不会直接采用作品。上传未完成时取消再重试返回 uploading，完整数据失败后重试进入后台校验。操作要求工程编辑权限，发布前重新检查成员权限。上传页面关闭会停止传输，但已确认偏移保留；完成上传后的后台导入不依赖页面。

`test_engineering_archive_transfer` 验证中断后只读取剩余字节、已完成素材不重复读取、清单变更拒绝、损坏部分文件不发布，以及独占锁在失败后释放。`test_engineering_archives` 使用真实持久化工程验证打包取消后恢复、完整归档内容校验、跨项目恢复、源数据库及存储移走后恢复渲染。

## 暂存容量和过期清理（0047）

创建、重试及执行前均校验全局配额、项目配额和磁盘余量。数据库全局咨询锁串行化预留，防止并发请求重复承诺同一空间。导出按媒体大小两倍加 32 MiB 估算；导入先预留上传量，校验清单后再为最大解包文件增加空间。容量只治理归档暂存，不等于永久素材库存储计费或租户总配额。

环境配置：ARCHIVE_STAGING_QUOTA_BYTES 默认 200 GiB；ARCHIVE_PROJECT_QUOTA_BYTES 默认 50 GiB；ARCHIVE_DISK_HEADROOM_BYTES 默认 512 MiB；ARCHIVE_RETENTION_DAYS 默认 7 天。磁盘检查保守扣除所有预留，已占用字节可能重复扣除，因此可能提前拒绝。部署应按实际持久卷容量调整，不能把配置配额理解成物理扩容。

后台清理超过保留期的任务暂存；运行任务、下载持锁期间均不删除。先持久化 purging，再仅删除该 UUID 目录内已知文件，最后释放配额；中途中断可重试，未知文件和路径重定向会拒绝清理。不会删除 CAS 原素材、作品提交或已导入候选。导入成功的状态保留，导出过期后可重新准备；过期上传须重新上传。下载锁在正常完成或断连时释放。

旧同步 /archive 接口也通过相同任务服务，不能绕过容量限制。浏览器仍使用分片/后台接口；旧 multipart 接口的请求解析临时空间不属于本暂存配额，大文件部署应限制该兼容入口的请求体大小，并使用分片入口。

测试覆盖真实 PostgreSQL 并发配额、项目/全局/磁盘拒绝后的事务回滚、下载持锁延迟清理、未知文件拒绝、清理中断恢复、过期上传重新准备。实际大容量吞吐和跨主机共享盘并未压测；上述证据证明状态与恢复机制，不证明 100 GiB 性能。
