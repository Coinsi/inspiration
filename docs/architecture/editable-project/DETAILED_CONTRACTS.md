# 工程细化契约与边界推演

状态：设计草案 0.3，2026 年 10 月 18 日。本文件补充六组工程契约；没有实现生产编辑器、渲染器或 Agent。已有 `example.json` 仍为格式 2 的最小样例，不宣称包含本文件全部字段。新增结构是待实现的版本化子契约，不原地改变格式 2 已有字段含义。

与 [基础契约](CONTRACTS.md)、[本轮校验记录](DESIGN_REVIEW_03.md) 配套。文中的“必须”是未来实现的验收条件；设计探针的覆盖范围以校验记录为准。

## 1. 时间、重复出现和同步

### 1.1 分段映射契约

`TimeMap@1 = {duration, segments, source_domain, audio_policy}`。所有时间继续使用有理数秒；下例为了阅读简写为数值，实际序列化使用 `{n,d}`。

每段为 `{id, local:[start,end), source_start, rate, join}`；`join` 为 `continuous` 或 `cut`。首段标记 `cut`，后段若为 continuous，其 source_start 必须等于前段结束处的映射极限。段 ID 不用数组下标；顺序改变不改变身份，切分时创建新 ID 并保存来源关系。

- 分段必须连续覆盖整个局部区间 `[0,duration)`，不得重叠、留洞或具有零长度。
- 段内 `s(t) = source_start + (t-start) × rate`。循环展开为重复段或版本化 repeat 结构；编译时有展开数量上限，不把无限循环放入有限交付工程。
- rate 可以为负；视频 rate=0 要明确 hold。音频另选 mute、stretch、resample 或 reverse 策略；hold 视频不能自动 hold 一段声音。
- v1 不解释任意函数或脚本。非线性速率曲线要登记新映射类型和可验证求值器，不能偷偷近似成常速。预览近似须记入降级清单。
- 源范围验证检查整个映射像，而非只看开始时间。不得把 endpoint 当成实际采样帧；实际 VFR 帧由时间索引和显式采样策略解析。

例：源 `[0,2)` 连续播放两次，再将源 `[4,2)` 倒放一次：

```json
{
  "duration": 6,
  "segments": [
    {"id":"first",  "local":[0,2], "source_start":0, "rate":1,  "join":"cut"},
    {"id":"second", "local":[2,4], "source_start":0, "rate":1,  "join":"cut"},
    {"id":"reverse","local":[4,6], "source_start":4, "rate":-1, "join":"cut"}
  ]
}
```

源事件 1 秒对应局部 1 秒和 3 秒。请求“改第二次拔剑”的目标必须包含 `second`，不能把检索结果的源时间直接当成时间线时间。

### 1.2 使用地址与 occurrence

地址为 `{commit, output, instance_path, segment_path, source_revision, range, space}`。instance_path 是稳定实例边路径；segment_path 是每层映射段/循环实例的身份。output 也属于地址，避免主片与预告片同名实例混淆。

嵌套求值从输出往源逐层应用映射：父时间减 placement，再应用该实例的 TimeMap，再进入子文档。路径上任一步越界、删除或修订不符，都不能自动就近绑定。

反向定位返回解集：零个解=`OUTSIDE_USAGE`；一个解=可定位；多个点或任意区间=`AMBIGUOUS_OCCURRENCE`。停帧段的逆像是区间，即使选了段，也必须选择显示区间或具体局部时间才能执行单点编辑。不能总取第一帧。

源修订变更后，锚点区分“几何时间仍可映射”和“原语义事件仍可信”。同样长度的新镜头不能继承旧眼睛跟踪、台词对齐或武器区域认可；旧分析保留，但需要重算或复核。

### 1.3 同步不是把所有东西绑死

`SyncConstraint@1 = {id, members, anchors, relation, tolerance, policy, revision}`。

| relation | 含义 | 示例 |
| --- | --- | --- |
| offset | 求值后的两个锚点相差固定时间 | 音画起点同拍 |
| shared_map | 两个使用共享一个明确的时间映射 | 分离出的原始视频和声音 |
| semantic_alignment | 对齐依赖源修订及分析修订 | 字幕词、口型、动态歌词 |

`policy` 为 hard 或 review；偏离 hard 必须拒绝，review 形成待复核项，不能偷偷解除约束。显式解除同步本身是一项可审阅修改。

局部音量改变不改变对白同步；替换配音内容要复核对齐，即使时长相同；由 4 秒变成 5 秒不能擅自拉伸字幕或后续镜头。可选择适配原时长、扩展片段并波纹移动、重新剪辑三种方案，所选方案进入 ChangeSet。

### 1.4 采样与变化范围

- 逻辑时间保持精确，直到媒体边界才量化。采样策略固定为版本化定义，例如视频 previous-PTS（且在有效显示区间内）、音频区间 `[ceil(start×rate),ceil(end×rate))`；禁止每个嵌套层逐次四舍五入。
- 时间映射的像/逆像可能是多个区间，必须保留区间集合；循环中的第一次变化不等于所有 occurrence 都被编辑。
- 在节点本地时间先扩展读取窗口，再沿映射传播。遇到不支持的非线性映射、状态模拟或无法证明范围时，对相关输出保守重算，不能少算。
- 缓存键含映射、采样策略、输入修订、效果与环境版本；代理媒体的 PTS/方向/色彩转换也要显式关联原始媒体。

## 2. 编辑命令的确定语义

### 2.1 所有命令共用的信封

```text
EditCommand@1 {
  id, operation@version, base_commit, target_address,
  arguments, scope, sync_policy, selection_revision
}
PreparedChange@1 {
  command_ids, actual_read_tokens, writes, affected_outputs,
  constraint_checks, review_units, before_after_summary,
  preview_spec, content_fingerprint
}
```

scope 明确轨道、实例、输出；不接受“全项目”作为隐含默认。服务端补全同步成员、布局、父映射、转场和权限读集。prepare 返回确定的移动/删除/生成清单；用户确认后不能重新选一批同名镜头执行。

### 2.2 常用命令的前后例子

时间单位秒。主轨原为 A `[0,4)`、B `[4,7)`、C `[7,10)`；B 源从 2 秒开始，rate=1。

| 命令 | 结果 | 必须拒绝或要求决定的情况 |
| --- | --- | --- |
| trim_end(A,3,ripple=false) | A `[0,3)`，B/C 不动，留下 1 秒空隙 | 非法零长度、源不足、转场失效 |
| trim_end(A,3,ripple=true,scope=主轨) | A `[0,3)`、B `[3,6)`、C `[6,9)` | 被移动对象受保护、同步成员未处理、跨越编辑点的其他片段未选策略 |
| trim_start(B,5,ripple=false) | B `[5,7)`，源起点由 2→3 | 不允许把它解释为整体移动 |
| move(B,5) | B `[5,8)`，源范围不变 | 与 C 碰撞；必须明确 overwrite/插入/换轨，默认不覆盖 |
| slip(B,+1) | B 仍 `[4,7)`，源起点 2→3 | 任一源/同步成员余量不足 |
| roll(A/B,-1) | A `[0,3)`、B `[3,7)`，B 源起点 2→1，C 不动 | 两边源余量不足、转场或 hard 同步不成立 |
| split(B,5) | 两个新实例 `[4,5)`、`[5,7)`，源连续；B 留在历史 | 关键帧、绑定或 occurrence 迁移有歧义 |
| replace_source(B,new) | 固定新源版本；默认保持位置/时长 | 新源不足或对白语义变化；不得默认循环/伸缩填满 |
| delete(B,ripple=false) | 删除 B 使用，保留空隙和源素材 | 删除共享源不是该命令的含义 |

split 派生新实例 ID 和 `split_from`，范围锚点按交集分配到两个实例；跨界锚点被拆成多目标。关键帧曲线在切点插入求值控制点，不能删除边界附近形状；曲线求值器未支持时拒绝该模式。trim 掉的关键帧可保留在源局部坐标，输出只取当前窗口。

### 2.3 波纹、同步和轨道保护

波纹移动由编辑点、位移和 scope 定义。片段起点在编辑点之后的整体移动；跨编辑点片段不自动截断，必须选择 split/move/leave，并检查同步约束。背景音乐常选择 leave，带口型对白通常跟随。

同步组传播到 scope 外成员时返回扩大范围的提案，不自动移动隐藏或锁定轨道。任何必要写入命中 protection，整个命令组失败；不能先改视频，再发现声音改不了。保护可细化 content/placement/gain，不把“锁定位置”理解成不能调整音量。

### 2.4 转场是一项双输入效果

`Transition@1 = {id, outgoing, incoming, cut, before, after, operator@version, curve, handles_policy}`。过渡区间 `[cut-before,cut+after)`，覆盖两个原本相接的片段，不通过同轨裸重叠表达。

居中过渡宽度 1 秒：A `[0,4)`、B `[4,7)`，cut=4，before=after=0.5。A 需要在其常规结束后再取 0.5 秒；B 需要在常规开始前再取 0.5 秒。常速时源余量乘绝对 rate；分段时必须实际扩展映射验证，不只用一个 rate。

余量不够默认拒绝；用户可以选择缩短转场、指定停帧或生成补帧，后两种是新增显式节点和候选。长度修改后需要重新校验过渡区间及相邻第三段，不能直接钳制而不告知。J/L cut 用独立音视频使用和同步约束表达，不强制两轨切点相同。

## 3. 图像、蒙版、音频的实际类型

### 3.1 图像端口细化

```text
ImageDescriptor@1 {
  extent:{width,height}, pixel_aspect:{n,d}, orientation,
  display_window, data_window,
  color:{primaries,transfer,matrix,range,icc_or_ocio_ref?},
  alpha: none | straight | premultiplied,
  sample_format, channels, coordinate_space_id
}
MaskDescriptor@1 {
  extent, coordinate_space_id, source_revision,
  time_domain, value_semantics:coverage, range:[0,1],
  outside:zero, interpolation, content_hash
}
```

生产 descriptor 中版本化 ID 必须能解析到受信任定义，不能只写“RGB”。蒙版是覆盖值而非显示颜色，不应用图像的 gamma/显示变换。0 不参与、1 全参与；反选显式节点。未知色彩可保留并提示，正式交付必须有明确解释或用户确认的转换配置。

统一显示空间：方向标准化后的图像左上为原点，x 向右、y 向下；尺寸 W×H 的像素中心是 `(i+0.5,j+0.5)`，归一化坐标对应边界 `[0,1]`。原始解码像素空间和显示空间各有 ID，通过显式变换连接。非方形像素先用 pixel_aspect 解释显示几何，不能仅匹配宽高。

二维变换使用列向量，`p_parent = M_parent_from_local × p_local`；嵌套按父矩阵乘子矩阵。矩阵含来源/目标空间、时间映射和修订。逆向选区遇到奇异矩阵不可求逆，返回 `NON_INVERTIBLE_SELECTION`。透视变换除以齐次 w，w=0 拒绝；三维投影通过单独适配器。

例：1000×1000 原图的眼睛点 `(250,400)`，实例放缩到 0.5 倍后平移 `(100,20)`，预览位置应为 `(225,220)`。用户圈选在预览坐标，要经过相同修订的逆变换才能成为重绘蒙版；不能把 225 直接当源图横坐标。

颜色转换、premultiply/unpremultiply、resize、方向归一化是编译计划里的显式适配器，可缓存但不可省略语义。默认合成在指定线性工作空间进行；预览显示变换与导出变换分开。零 Alpha 的反预乘定义 RGB=0，避免除零；不能从完全透明像素保证恢复隐藏原颜色。HDR→SDR 需版本化 tone-map 和交付配置，不能当作普通 8-bit 截断。

### 3.2 音频端口细化

```text
AudioDescriptor@1 {
  sample_rate, sample_format,
  channels:[stable speaker labels], layout_definition,
  time_origin, valid_sample_range,
  processing_latency_samples, tail_samples
}
AudioRoute@1 {
  source_port, destination_bus,
  channel_matrix, gain_or_curve, converter_refs
}
```

声道数量相同不代表布局相同；双声道对白可为两个独立人物，不能默认 stereo。映射矩阵形状为 output_channels×input_channels，标签顺序进入指纹。无显式矩阵/受信任转换规则时禁止自动 mono/stereo/5.1 互转。

重采样单独适配；gain 以 dB 表达，静音用 mute 不用负无穷。响度目标、限幅、峰值检查和响度测量记录分开；“-3 dB”不等于“-3 LUFS”。混音允许浮点中间超峰，交付前按指定策略测量/限幅，不能仅凭合法增益判定声音合格。

并行路径在汇合点按同一时钟比较累计延迟，较短路径增加补偿延迟。44.1k 与 48k 的样本数不能直接相减；先转成有理数时间，再由适配器采样。lookahead 是处理延迟，混响 tail 是额外输出范围，两者不能混用。

例：同一 48k 时钟两路分别延迟 240/960 样本，前者补 720 样本，后者补 0；不会把对白的工程位置永久移动 15ms。渲染需额外预卷，再按工程时间裁出输出。显式反馈/延迟效果需专用有状态节点，不允许普通路由出现无延迟环。

用户说“这段声音小”，先确认独立对白轨或混音源；混音源没有可直接改的人声层，必须先分离/重配产生候选。该事实进入能力判断，不用假层结构掩盖缺少工具。

## 4. 多对象修改、采用和撤销

### 4.1 修改单位与共享路径

`ChangeGroup@1 = {id, commands, requires_groups, invariant_ids, affected_addresses}`。组内原子，跨组有明确依赖；“部分采用”只能选择闭合的组集合，不能把一个组中的任意 JSON 字段挑出来。

示例：G1 新配音，G2 新字幕要求 G1，G3 新口型要求 G1，G4 新封面独立。只采用 G2 拒绝；选 G1+G2 若原口型因此不成立，也必须连同 G3 或明确解除口型要求一起审阅。依赖闭包不等于所有创作不变量都自然成立，提交仍要校验。

多条路径共享同一旧合成时，先形成“所选地址树”，按每个位置预期修改分组，再由叶到根构造新修订。同一旧修订在两处要求不同结果时必须分叉，不能以旧对象 ID 为全局 memo 键把两处改成一样。相同修改可复用新叶修订，但每个父使用独立改引用；未选输出保留旧根。

数据访问范围由主体权限决定，地址不能跨租户。跨作品复用新结果仍需资源授权和保留记录，不因合并工程而继承另一作品管理员身份。

### 4.2 合并和审阅指纹

三方信息是 base、candidate、current；服务端提取实际读写/关系依赖。稳定对象/组件身份决定匹配，数组位置或名称不能决定合并。

- 不同叶字段但共享时长/轨道顺序/身份约束仍可冲突。
- 同一实例 delete 对 edit、reorder 对依赖原顺序的插入、旧源引用对新跟踪都需冲突处理。
- 只发生无关变化，可以重放命令并复验；不得用 candidate 全快照覆盖 current。
- 审阅证明绑定选定组、实际读写令牌、最终候选内容指纹、输出与预览规格、保护约束和所看产物。HEAD 无关变化本身不必作废，但影响任一已审内容或语义前提必须重新审阅。
- 内容指纹用规范编码和内容哈希生成；不能使用不稳定 dict 序列化或临时 URL。

### 4.3 撤销不是写回旧整份工程

提交回执保存 commands、before_refs、after_refs、读写令牌和逆操作可用性。选择性 undo 构造新的候选变更：只有当前被写位置仍处于原提交后置令牌、依赖仍满足，才能安全使用逆操作。无关封面变化保留；若音量后来又改过，即使值刚好相同，也冲突。

结构命令逆操作需恢复实例、顺序、同步和锚点关系，不能通用逐字段减法。生成请求不能“逆生成”或退款；undo 只撤销采用，文件按保留策略处理。restore 是创建引用旧内容的新提交，必须展示被回退的后续修改；不会删除历史。

审阅界面默认展示“改了哪些片段、需一起采用什么、影响哪些成片”；后台的组、端口和令牌不变成用户必填表格。

## 5. 格式迁移、导出和扩展

### 5.1 兼容清单

包头分别记录 `package_format`、`required_features`；对象记录类型/schema 版本；操作实现版本不与包版本混用。新增可选信息不自动要求迁移，改变既有字段语义必须升级对应 schema。

扩展分 critical 与 advisory。未知 critical 扩展参与执行/依赖时，保留但阻止相关运行与编辑；未知 advisory 可保留并跳过显示。已知类型的未知字段仍完整往返；旧客户端用受约束领域命令更新，不允许重序列化自己理解的几个字段覆盖全对象。

未知载荷里可能隐藏 ID：扩展需要 envelope 声明 reference_manifest 和可信重写适配器。不能对所有字符串做 ID 替换，也不能导入后假装隐藏引用已重映射。不透明且无引用声明的对象只可原样归档；不得挂到可执行根。

### 5.2 格式 1 → 2 的明确迁移

先保存原包哈希和只读备份。每个旧根要求明确目标规格：image、silent_video、audio、av；av 额外选择同一根中的声音端口。迁移器不能把旧 video 根自动当成静音。

迁移生成新包和迁移报告，不改旧对象载荷或抹去原提交。报告包含 source_hash、migrator_version、decisions、warnings、target_hash。目标规格没有已注册实现时标记不可执行；当前最小探针只覆盖 image/av，其他规格需正式适配器。

迁移按源版本一次一跳，拒绝版本倒退和未知未来版本。重复输入与相同决定产生相同规范内容；不将当前时间和随机 ID 放入需确定的迁移内容，审计事件独立保存。缺少声音、引用损坏或不满足新约束时迁移不发布。

### 5.3 导入导出与真实性

导出指定输出/提交的引用闭包、选定历史和所需 blob；列明未带媒体/插件/字体。导入先暂存、校验清单和 hash、分配命名空间映射、通过类型适配器重写规范引用，再整体发布。任一步失败不能出现半个可用作品。

对象 ID、组件 ID、分支/作品 ID 各有作用域；blob 内容哈希通常不改，物理 URL 不进入可迁移身份。跨租户复制创建目标授权/逻辑归属，原账户的权限和外链 token 不导入。

只读打开、不透明往返、可编辑、可渲染和可交付分别报告。旧格式成功解析不等于像素/声音等价；格式迁移最终还需要真实媒体的黄金样例对照。

## 6. 资源存续、删除和运行恢复

### 6.1 保留根与删除

保留根包括当前分支、用户钉选/发布版本、保留期内历史、未过期候选、运行输入/输出租约、导出中的快照、审计/法定保留策略。它们的闭包决定逻辑资源存续。父提交链接不意味着永久保存全部历史；历史保留集必须显式定义。

回收站是逻辑删除并设 grace_until，既有引用仍可保留；立即禁止新采用的政策可独立设置。撤销访问不等于物理文件立即消失；物理文件仍存在也不等于继续有权读取。

回收采用：候选标记 → 隔离等待 → 最终事务复核根/租约/删除状态 → 标记 deleting → 删除物理 blob → 记录完成。新引用或租约发布必须与 deleting 检查使用同一并发协调机制；删除中的 blob 禁止新租约或先可靠恢复，不能只“再查一次”就认为无竞态。

每次物理删除使用独立 delete_operation_id，锁定存储对象的 generation/ETag 或不可覆盖的物理键。删除后回执丢失要查询该对象并恢复回执；不能误删同路径后来上传的新对象。只有数据库状态变为 deleting 不代表物理删除已经完成。过期租约只有在工作者被 fencing 后才可回收，不能把心跳延迟当成确定停止。

共享 blob 按所有租户有效逻辑引用和租约统计，单租户删除不能删另一租户的内容。哈希查重不能返回其他租户是否持有该素材。删除缓存只影响可重算产物，已采用的随机生成媒体属于受保护输入。

源使用权撤销时，受影响执行/新导出停止；已有导出副本无法假装远程撤回。保留历史可显示占位和原因，不能自动替换同名素材。正式保留天数、费用额度和许可政策是部署配置，不在格式里硬编码。

### 6.2 任务分层和幂等

```text
Run：一个用户意图的执行记录，固定输入快照、要求、预算与候选目标。
Attempt：一次实际执行尝试，含 provider、request_fingerprint、幂等键和外部任务 ID。
Receipt：提交/计费/结果回执，只追加；账单事实独立于 UI 的取消状态。
```

幂等键作用域含 tenant、operation、logical_request。相同键相同内容返回已有回执；相同键不同内容返回 `IDEMPOTENCY_KEY_REUSED`。服务端持久化参数指纹，不只依赖内存缓存。主动“再生成一版”是新意图/新键；断线重试同一请求继续使用旧键。

| 当前状态 / 事件 | 下一步 | 禁止行为 |
| --- | --- | --- |
| queued / worker 获得租约 | submitting；先记录 attempt | 先扣费发送再无记录 |
| submitting / 返回 job ID | running；保存外部 ID | 丢 ID 后立即再提交 |
| submitting / 网络超时 | outcome_unknown；查询/对账 | 当成确定失败自动收费重发 |
| outcome_unknown / 查到任务 | running 或结果发布 | 重建第二个逻辑任务 |
| running / 结果通知 | 验证、下载、hash 后发布候选 | 收到 URL 就宣告工程采用成功 |
| running / 请求取消 | cancel_requested；尽力取消 | 声称供应商已取消或已退款 |
| cancel_requested / 晚到成功 | 记录计费与候选；抑制自动采用 | 覆盖用户改过的工程 |
| 完成 / 重复或乱序通知 | 按事件/外部任务身份去重，单调归并 | 回退到 running 或产生重复候选 |
| worker 过期 / 新 worker 接管 | fencing token 防旧 worker 提交；恢复 checkpoint | 仅靠本机锁防双写 |

外部供应商没有可靠幂等/查询时，无法保证跨网络 exactly-once。结果不明进入待处理，不以重新收费请求掩盖不确定性。可以保存用户授权的新尝试，但须明确可能产生重复结果/费用。

内部工程提交、幂等回执和 outbox 同事务；投递允许重复，消费者去重。工作者锁不跨整个长任务；进度不是工程真相。权限在提交外部任务、取回媒体、发布候选、采用/导出时重新检查；过期 token 不能代表永久授权。

权限撤销后的供应商成功/收费回执仍记入受限审计，不向已无权限者发布素材。外部结果只能按服务端策略隔离或丢弃，不能为了完成 UI 状态而重新授权；此时不会触发另一次生成。预算在请求前预留、结果后对账，取消不提前假定退款。

恢复 checkpoint 保存输入/实现版本、已完成步骤回执、可复用产物与状态代次。模型/实现已不可用时保留旧候选，重新规划作为新 attempt；不声称无损续跑。资源不足可暂停或返回可选降级，不能偷偷降低最终规格。

## 7. 这些契约怎样承接创作需求

| 用户指导 | 工程表达 | 确实还要实现的能力 |
| --- | --- | --- |
| 第二次出现时把眼神改一下 | output + 实例/segment 地址、源空间蒙版、新候选、局部采用 | 人物定位、视频重绘、一致性检查 |
| 这一句声音小一点 | 对白使用的增益曲线，保持同步/源内容 | 音频解码、混音与响度验收 |
| 换配音但字幕和口型得跟上 | 有依赖的变更组与 semantic_alignment | 配音、对齐、口型、合并预览 |
| 武器精致些但其他镜头不动 | 所选使用路径分叉、旧角色/区域保留要求 | 局部生成与区域外变化评估 |
| 打斗精彩一点 | 场景级候选分支；剪辑/补镜/音效分组，审阅整段 | 创作规划、检索/生成、节奏评价 |
| 剑光穿过身体时要被挡住 | 同时间/空间的轨迹和遮挡蒙版、显式色彩/Alpha 合成 | 跟踪、抠像、合成渲染 |
| 动态歌词随配乐变速 | 对齐修订、TimeMap、稳定字/词 ID、动画子合成 | 字体排版、逐字对齐、文字动画 |
| 只要这版的声音，画面保留 | 部分采用闭包 + 当前画面同步复验 | 组合预览和用户确认 |
| 任务还在跑，推翻这段剧本 | 新要求修订、依赖影响、取消/隔离旧任务、保留候选 | 上层调度与重新规划 |

工程给出了可落地的承载位置和拒绝规则，不能独自保证创作效果。实现中的每项能力仍需对应工具、媒体执行器、质量验证和恢复验收。

### 串联推演：多个任务在运行时，用户改一段配音

假设 C10 是正在制作的 5 分钟短片工程提交，不能理解成现在已能生成该短片。

1. 对白任务 A、歌词任务 B、封面任务 C 各固定自己的输入和实际读集。B 读取的是对白/音乐的具体版本及映射，不是整段聊天文本里的“那段声音”。
2. 用户指示“第二次出现时换紧张一点的声音”。选择上下文解析到主片中的确切使用地址；其他使用和预告片暂不修改。原共享配音修订不覆盖。
3. 系统对这个地址产生新要求修订和候选组。A 的旧要求已过期，尽力取消或让其结果只进入旧方案候选。C 未读取配音与相关剧情，可以继续；B 是否停止由依赖读集与任务用途决定，不能全停或全继续。
4. 新声音从 4 秒变成 5 秒。先形成三种处理方案的影响摘要，不暗中移动后续内容。若选择延长，波纹范围、同步组、转场、原背景音乐锚点和字幕都进入完整变更。
5. 一条受保护对白轨阻止波纹方案时，工程保持 C10/当前 HEAD 不变；候选声音保留。可以提出适配 4 秒或重新剪辑方案，不能解锁后悄悄继续。
6. 用户采用完整有效组，生成 C11。若封面任务已提交 C10→C10a，声音方案重放到 C10a，保留新封面；已审内容受到影响时重新审阅。声音和必要字幕一起落地。
7. B 的旧字幕或 A 的旧配音晚到后仍绑定旧输入，不能写 C11。用户若想取用其一，重新形成针对 C11 的采用提案及对齐校验。
8. 渲染 C11 输出附带输入提交和规格。撤销这次采用创建 C12，保留之后无关的封面修改；若用户又改过相同对白，则撤销冲突转为候选方案。

这是跨模块设计走查，尚不是端到端执行测试。它要求任务调度、工程提交、素材版本与审阅共同遵守契约；只实现其中一个接口不能宣称闭环完成。

## 8. 冻结边界

本轮明确六组契约的决策与正反例。可以据此拆工程内核的实施任务，但尚不冻结所有扩展格式：非线性时间曲线、三维/模拟、HDR、多语言多总线输出等须按适配器独立版本化。

内核冻结前必须完成：正式 schema/规范编码、真实事务和资源租约协议、旧数据迁移清单，以及最小媒体执行可行性验证。本轮只做设计，不以待执行的验收冒充验证通过。
