## 反例所揭示的关键要求

1. **源时间不是唯一使用位置。** 循环中源 1 秒分别映射到局部 1 秒和 3 秒；必须选 occurrence。停帧选中 occurrence 后仍然可能对应一个区间。
2. **单字段修改不一定局部。** 视频波纹移动而留下同步对白必须失败；被保护的一个成员会阻止整组，输入状态不变。
3. **同为图像或音频也未必兼容。** 空间修订、Alpha、色彩和像素比例差异需要明确转换；441 个 44.1k 样本与 480 个 48k 样本时间相同，不能直接按样本数补偿。
4. **共享源不等于共享采用。** 主片两处可分别采用新修订 2 和 3，预告片保持修订 1。一个全局 source_id → new_revision 映射不能满足这一点。
5. **撤销也需要版本前提。** 当前数值和之前一样、但修改令牌已更新，仍需拒绝无条件撤销；无关新封面必须保留。
6. **回收前复查不足以防竞态。** 标记后新租约使旧删除计划过期；开始删除后必须拦新引用，并用数据库/存储协议实现这种互斥。
7. **取消与完成可以同时发生。** 晚到成功可以保存候选及计费事实，不能因成功就自动采用。供应商结果未知时，禁止直接重复付费请求。

这些规则来自设计中的具体反例和纯状态模型，不是对现有线上系统漏洞的宣告。

## 决策与待定的区分

已确定的方向：不可变版本、使用级采用、时间/空间显式映射、变更组原子性、未知能力阻断、保留根及任务幂等，不再由每个 Agent 自己决定。

待具体实现验证：渲染器与色彩库选择、非线性变速/复杂模拟、完整格式迁移实现、数据库锁粒度、对象存储删除协议、队列恢复。保留期、预算上限和租户并发配额采用部署政策，不把某个任意数值写死在工程格式里。

尚不承诺：艺术质量、任意专业软件无损往返、任意供应商 exactly-once、任意扩展都无需迁移，以及数百 Agent 的实际吞吐。
