## 接口

前缀：`/api/v1/projects/{project_id}/works/{work_id}/engineering`。

| 路径 | 行为 |
| --- | --- |
| GET 空路径 | 当前资源清单、修订、能力；明确 `renderable: false` |
| GET `/history` | 分页读取已提交版本 |
| GET `/changes` | 分页读取候选/采用回执 |
| POST `/changes` | 提出 `resource.add`、`resource.remove` 或独立 `restore` |
| POST `/changes/{id}/accept` | 校验 fingerprint 和当前版本后采用 |

`engineering.edit` 允许管理员、导演、创作者、编剧提出候选；`engineering.adopt` 允许管理员与导演采用。默认只读成员不能写。请求 schema 拒绝未知字段，命令最多 100 条；本阶段资源清单最多 1000 次使用，是实现保护上限而非未来格式限制。

示例请求（ID 使用实际项目数据）：

```json
{
  "request_key": "<UUID>",
  "base_revision": 0,
  "commands": [{
    "operation": "resource.add",
    "usage_id": "<UUID>",
    "source_kind": "library",
    "source_id": "<MediaVersion UUID>",
    "name": "开场参考"
  }]
}
```

生成结果用 `source_kind: generation` 和 Generation ID。采用请求传候选返回的 fingerprint。该指纹绑定不可变候选的原请求；尚不是设计中的媒体预览审阅签名，不能据此授权付费生成或自动采用。

## 第二批：时间线只读快照桥接

新增 `timeline.capture` 命令，参数为 `timeline_id` 和 `timeline_revision`，继续通过候选/采用接口进入工程。捕获前校验所属项目和时间线修订，错误不产生候选。作品写入现在统一先锁项目再锁作品，与旧时间线的锁顺序一致。

快照格式 `studio.timeline_capture@1` 保存旧编辑文档与固定渲染输入：画面片段、音轨、字幕、叠加层及素材哈希。生成结果同时登记为工程资源引用；依赖不能通过普通资源移除命令单独删除。重复捕获同一条时间线替换该条快照，不重复堆积资源使用。

`generation.jobs.timeline_render_snapshot` 是旧时间线导出和新捕获的共用转换入口。捕获不会创建渲染任务，也不修改时间线。候选采用的是捕获时的历史快照，之后时间线改变不自动改变它；它不是实时关联，也不能据此覆盖后来修改的时间线。

边界：当前片段身份来源于旧行 ID，音轨身份使用旧 ordinal，仅保证同一旧版本的重复转换一致。旧编辑器保存会重建片段，因此尚未实现跨旧编辑版本的稳定身份。工程 API 仍返回 `renderable: false`，尚无工程渲染任务入口、编辑回写和审阅界面；不能把此桥接宣称为完整剪辑迁移。

新增测试覆盖固定快照、候选不修改旧编辑器、重复请求、旧修订拒绝、跨项目拒绝、依赖保护、重复捕获和快照通过既有 FFmpeg 渲染器编码/解码。真实编码测试使用合成图片，不涉及用户原始文件或付费模型调用。

## 第三批：剪辑候选到采用的完整闭环

### 用户入口

在「剪辑成片」中调整片段、音轨、字幕或叠加画面，点击「作品审阅」，选择或新建作品：

1. 将当前剪辑保存为候选；现有时间线不变。
2. 生成候选预览，在同一个窗口播放。失败时显示原因并提供重试；关闭窗口后任务继续，重新打开可选择已有候选。
3. 确认采用。时间线、历史记录和作品修订在同一事务中更新；前台载入已采用内容。
4. 在工程历史中选择版本，恢复为一个新候选，预览后再确认采用。首次采用前的时间线仍在原有剪辑历史中保留。

候选显示新增、修改、移除或顺序调整摘要。若其他人已经修改作品或时间线，采用返回冲突而不覆盖。可载入最新时间线重新编辑；载入前会明确确认是否替换本地未保存草稿。

### 数据和执行契约

- `timeline.edit` 接受既有 `TimelineDocumentIn` 和时间线 ID；`timeline.restore` 接受工程历史修订与当前时间线修订。两者一次仅修改一条时间线，不能混入其他命令。
- `prepare_document` 是草稿与正式保存的共用校验路径；`document_render_snapshot` 冻结实际 Generation、文件哈希、音轨、字幕、叠加层和媒体区间。没有选定来源时拒绝预览，不猜测替换素材。
- 片段和音轨现在更新原行，保留 ID；字幕也保存 ID。拆分片段的后半段使用新 ID。旧客户端缺少 ID 时按现有对应项补齐；这种兼容映射不能恢复旧历史中从未记录的真实身份。
- 新接口：`GET /changes/{id}` 返回候选及预览状态，`POST /changes/{id}/preview` 创建本地 FFmpeg 任务。任务和候选关联先一起提交，再派发执行。正常重复请求返回同一任务；失败重试携带旧任务 ID，重复重试不创建多份任务。
- 预览始终读取不可变候选，使用 720p、所选画幅、完整混音和烧录字幕，不受之后的草稿编辑影响。预览结果带工程来源标记，不混入时间线普通成片列表。
- 采用要求预览成功且结果存在，重新校验工程源、权限、工程修订与时间线修订。唯一最终写入口仍是 `editing.save_document`；不会建立第二套独立可写时间线。
- 候选预览失败不改变当前作品或时间线。采用重复调用返回原提交；并发采用只允许一个成功。
- 迁移 `0039_engineering_timeline_review` 增加候选的时间线更新内容与预览任务关联；已在本地开发库升级并核对原作品、时间线身份与修订不变。有剪辑候选时拒绝直接降级丢弃审阅信息。

### 验证与明确边界

新增真实 PostgreSQL/FFmpeg 测试包含：编辑不提前写入、预览成功后采用、失败重试幂等、历史恢复、预览期间外部编辑冲突、跨作品隔离、稳定 ID、音轨/字幕/叠加层一起修改，以及两个数据库会话同时采用。

浏览器测试 `frontend/tests/engineering-review-browser.mjs` 使用隔离 API 夹具，验证候选、失败重试、视频播放、确认采用、历史恢复候选和窄屏布局；不会更改用户项目。产物在 `frontend/test-results/engineering-review/`，运行需要 Playwright、Chrome 和已安装依赖的后端虚拟环境；脚本自动生成合成图片与视频。后端测试使用临时 PostgreSQL schema 和临时本地文件，不调用付费模型。

这次闭环复用当前剪辑能力（最多 100 段、30 分钟、现有音轨/字幕/叠加限制），没有实现完整 AE 式合成器。任意特效插件、蒙版、跨对象自动合并、多 Agent 调度、候选垃圾回收、任意工程包导入导出均不在此目标内。工程 GET 的 `renderable: false` 表示不提供任意工程 HEAD 直接渲染，已支持的是剪辑候选预览。前台工程列表当前展示最近 30 项，接口支持 offset 分页。

最终验证：12 个相关后端测试文件共 68 项通过（含真实编码、混音、字幕、转场与并发测试），前端编辑测试 3 项通过，浏览器完整审阅路径通过，TypeScript 类型检查、生产构建、相关新增 Python 模块 Ruff 检查和 `git diff --check` 通过。生产构建仍有既有 Director 分块体积提示，不影响构建成功。

## 第四批：持久化编辑文档与固定依赖

作品创建在同一事务内建立空 `work.manifest@1` 文档修订，工程采用版本仍为 0。创建工作剪辑或显式关联已有剪辑时建立 `sequence.timeline@1` 文档和 `resource@1` 叶子。不会复制原始媒体，不会自动生成成片。

### 存储与写入

- `engineering_document` 是稳定身份、类型、所属作品与可选的时间线适配关联；`engineering_document_revision` 保存固定输入、载荷、格式版本和内容 SHA-256。
- 工程清单的命名输入引用明确的文档 ID 与修订；画面和声音共同引用一个剪辑根。依赖闭包按作品权限校验，拒绝失配、循环与超过保护上限的遍历。
- 文档修订只追加，不原地覆盖；内容相同复用已有修订。工作剪辑指针保存在 `work_timeline.document_revision`。工作修订、候选和已采用工程版本不混用。
- 现有时间线仍是工作编辑投影的唯一写入口，普通保存与相关作品文档修订在同一事务内完成。共享时间线保存会推进相关作品的工作文档，不改变其已采用快照。
- 候选建立固定 `document_ref` 与 `manifest_ref`。新候选预览从固定文档与固定资源解析，采用再次校验并从文档载荷恢复编辑投影，不以最新文档替代固定输入。
- `document.edit` 支持从指定修订修改，或不提供新载荷时恢复为候选。旧时间线版本前提或旧工程版本前提均拒绝写入。预览成功后才可采用。

### 类型边界

`document_types.py` 集中注册类型及版本校验。当前可执行剪辑适配器是 `sequence.timeline@1`，显式使用既有毫秒时间、片段、音轨、字幕与有限叠加语义；不是设计草案中完整的有理数时间、嵌套合成与效果图格式。未知类型不会静默丢弃后渲染。

图像图层、独立音频文档、嵌套合成、蒙版、关键帧、复杂特效、多文档原子编辑、分支合并、Agent 工具接入仍须对应实现。这里实现的是统一持久化/修订/引用基础与现有剪辑的可执行闭环，不应将设计 0.3 全部标为落地。

### 接口与界面

- `GET .../engineering/documents`：类型能力、工程文档及修订列表，区分工作修订。
- `GET .../engineering/documents/{id}/revisions/{revision}`：读取固定修订，跨作品访问拒绝。
- `GET .../engineering/manifest?revision=N`：读取指定已采用工程的清单及依赖闭包；返回明确的 `includes_media_files: false`。这是引用清单，不是可携带媒体的导入导出工程包。
- 作品详情新增“工程内容”：选择修订、固定内容快速预览、从旧修订建立候选、返回工作剪辑。旧项目可显式接入已有剪辑；旧候选与历史不被改写，旧预览保留兼容读取。
- 新迁移 `0041_engineering_documents` 增加两张表与工作文档指针；有文档数据时拒绝破坏性降级。本地开发库已升级。

### 验证

新增真实数据库与 FFmpeg 测试验证：创建空清单/空剪辑、保存和重新读取、旧内容不变、从文档修订修改与恢复、真实候选渲染及采用、历史闭包保持不变、跨作品拒绝、时间线回收后仍可读取固定文档、校验损坏拒绝、未知操作拒绝。另验证迁移升级与空表回退，原数据保留。

浏览器夹具验证工程内容页、修订预览、建立候选后准确进入审阅、手机无横向溢出；不调用付费模型、不修改用户作品。

## 合成第二版实际执行（2026-10-18）

- `studio.composition.ffmpeg@2` 固定新身份，接收 `composition.document@2`，混合嵌套第一版合成时只在执行计划内显式规范化，原修订/校验和不变；第一版执行器继续拒绝第二版。
- 按每个使用实例的分段 TimeMap 计算源时间；正向和停帧取不晚于源坐标的帧，反向取源坐标左极限帧。使用整数/有理数，片尾倒放不会采样右开域之外的空画面。
- 重复、倒放、停帧均通过实际像素检查及 MP4 编码后解码逐帧检查；混合版本嵌套文档通过数据库候选和任务预览链路。同步复核采用仍必须显式确认。
- UI 基础画布/音量编辑可读取并保留第二版结构；不把此入口描述为完整时间映射编辑器。
- 仍仅支持静态图像层与嵌套画面合成，不支持视频源解码层、声音混合、曲线、特殊混合、旋转缩放；合成声音策略不是 none 时明确拒绝。音频第二版尚无执行器。编码沿用有界 MP4 预览限制。


## 音频第二版实际执行（2026-10-18）

- 新执行器 `studio.audio.ffmpeg@2` 固定身份，支持 `audio.document@2` 并显式读取旧版嵌套音频。输出仍为 PCM16 WAV，固定第一音频流；媒体哈希校验和任务取消沿用工程任务协议。
- 每段映射先解码验证完整源区间，再进行重采样（改变音高）、保音高变速、倒放或明确静音。重复映射各有独立放置位置，轨道/片段增益随后混音；停帧仅支持明确静音，并验证源位置确实存在。
- 源和目标边界必须对齐输出采样网格。执行速率范围 1/16–16 倍；重采样要求换算采样率为整数；每文档最多 64 映射段、嵌套展开最多 256 次、输出及单段源范围最多 30 分钟。
- DSP 尾部允许的拟合不超过 50ms 且不超过目标时长 10%；变速完全没有输出或超出误差时失败，不允许整段补静音伪装成功。源素材不足始终失败。此预览执行器不是母带级音质或无缝拼接保证。
- 实际 PCM 测试覆盖重复、倒放、静音停帧、变速音高区别、精确总采样数、旧版嵌套音频、超源范围、非采样对齐和短段变速失败；持久化 API/任务测试覆盖两版音频文档与正确 MIME，候选不自动采用。

### 2026-10-18 CAS 物理身份与并发发布

- 逻辑内容仍以 SHA-256 去重；新物理对象使用 `<hash-prefix>/<hash>.<uuid>`，正常命中保持原 URI，修复或强制恢复生成新 URI。旧路径读取继续兼容。删除重试必须持有捕获的旧 URI，不得根据 hash 拼接当前 URI。
- CAS 写入和修复在 PostgreSQL 事务中取得按哈希的 advisory lock，直到提交；相同内容的并发发布会重读已提交对象，避免四个上传各自发布不同实体。
- 真实 PostgreSQL/文件系统验证修复路径不重用、普通去重、旧路径延迟删除不会影响新对象、缺失文件重新上传修复；对象存储分支用隔离 Store 适配器验证旧 key 删除不影响新 key，不声称该项是真实 MinIO 网络验收。
- 尚未启用物理 GC。本项只是安全删除所需的不可重用物理身份与写入协调，读者租约、新引用与删除互斥、删除回执仍待实现。
