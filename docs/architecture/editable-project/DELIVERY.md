# 作品工程底座交付关口

2026-10-18。用户要求持续完成能承载后续功能的工程实践。不能以时间线适配或几项演示完成代替这个交付。本文是实施关口，不是已完成声明。

## 完成标准

1. 类型化文档：图像、音频、合成、剪辑共享身份、修订、引用和校验；格式及执行支持分别声明。
2. 多文档修改：候选固定基线，一次事务采用；冲突不部分覆盖；旧结果仍可查看。
3. 依赖：跨文档引用固定版本，识别受影响输出；局部修改不会自动升级所有实例。
4. 保存与恢复：重开内容不变、历史可读可恢复；工程包包含校验信息、依赖闭包及明确的外部媒体缺口；导入不覆盖原工程。
5. 扩展：新增业务通过版本化类型/操作/执行适配器接入；工具与 Agent 不拥有独立的作品状态。
6. 页面：作品可看见文档、采用版本、候选、依赖缺口和可继续编辑入口；不能只在 API 中存在。
7. 验证：持久化、失败回滚、并发基线、历史、导入导出和现有时间线回归；执行能力用真实媒体验证。

不承诺此轮实现所有高级特效算子，但不支持的算子必须明确拒绝执行。可保存的格式不等于可渲染；未来扩展仍需版本升级和迁移。

## 执行与引用治理增量

- 执行器按不可变 ID 注册，文档类型/格式版本解析默认执行器；排队计划冻结所用执行器，替换默认实现不改变旧任务。统一工程任务路径调用适配器，能力清单由注册器产生，不能将支持某个子集误称为支持整个格式。
- `studio.audio.ffmpeg@1` 实际输出 PCM WAV：支持固定音频或视频的首条音轨、源区间裁剪、采样对齐的放置、轨道/片段增益与静音、多轨混合和嵌套音频。采样越界拒绝；流式校验源文件，临时文件随执行清理。逐样本测试验证位置和 -6 dB 增益，持久化任务验证 audio/wav 类型。
- `studio.composition.ffmpeg@1` 实际输出无音轨 MP4：支持图片层显示区间、嵌套合成和有理帧时间。逐帧测试检查半开区间和子合成源偏移；真实任务测试检查输出 MIME 和预览不自动采用。当前不支持视频源、关键帧、复杂混合或透明视频输出；执行前拒绝，不能忽略这些内容后声称成功。
- 候选页面依据执行器注册信息提供预览，支持图片、音频与视频结果。原生文档保存仍然不自动触发渲染。
- `document.retarget` 按文档的输入端口显式升级固定引用，核对文档版本和原引用，可引用同批候选子文档；其他父文档不变。此操作以端口为单位；多个图层共享同一个端口时都会受影响，尚不等同于逐实例拆分端口的编辑工具。
- 作品读取和列表不再依赖关联剧本是否在回收站；剧本是可选关联，不拥有工程生命周期。回归覆盖剧本回收后仍能访问作品工程和剪辑关联。
- 同一候选现在可包含一条剪辑的修改和多份原生文档，采用时一起提交。剪辑仍需真实预览；审阅摘要明确列出同时采用的文档，剪辑预览不代表其他输出的渲染验收。测试验证成功时共同采用、剪辑版本竞争时不部分采用原生文档。多条剪辑的原子写入尚未开放。

以上不是本目标完成声明。自包含媒体迁移、未知格式保留、跨类型写入所有权和通用工具治理仍需继续落实。

## 未安装扩展的保存边界

- 未注册的扩展类型/格式版本允许作为只读文档保留，通过公共固定引用封套校验、闭包校验和内容哈希校验。未知内容不执行、不开放 `document.put` 修改；核心资源/清单/旧时间线格式不能借未知版本绕过校验。
- 工程包导入保留未知 payload、schema 版本和输出流声明；跨作品重新分配文档身份后仅重写公共 inputs 引用。扩展格式必须把可迁移的跨文档依赖放在 inputs 中，payload 内的业务值原样保留，不猜测其中的 UUID。
- 已安装的扩展移除后，历史仍可读、工程仍可导出，修改其他文档不会移除未知内容。输出流声明随作品快照保存。
- 页面展示保留状态与原始内容，未知格式不出现修改按钮；已知页面也不会把未来 schema 版本当作版本 1 编辑。新增 API 测试覆盖未知格式往返、执行/编辑拒绝、移除适配器后修改其他文档不丢数据。

## 媒体归档推进

- 新增 `GET /engineering/archive`：导出 `studio.engineering-archive@1` ZIP，包含引用包及按内容哈希命名的全部媒体。使用 ZIP64 和分块复制，不把大视频读入内存；每份媒体重新校验大小和 SHA-256，响应完成清理临时归档。当前单次媒体总量上限 100 GiB。
- 归档校验器验证描述、依赖清单和全部媒体字节，拒绝额外路径、重复成员、加密项、内容篡改及超限数据，不执行解压到用户提供的路径。真实数据库导出测试已覆盖完整媒体、内容篡改及目录穿越条目拒绝。
- 正在解除旧剪辑对镜头记录的强依赖：新增迁移 0042，允许片段仅引用同项目固定媒体；DTO 保证至少有镜头或媒体来源，原有镜头归属校验保留。前端提供独立片段名称回退。迁移尚未在用户运行库应用。
- 归档恢复和页面入口尚在实现，不能把当前 ZIP 导出称为完整跨实例恢复已完成。

### 恢复链路增量

- `POST /engineering/archive` 接受完整归档并恢复到空作品；先校验全部媒体，再写入 CAS 和目标项目自有的导入溯源记录。重新绑定媒体身份和剪辑片段，原镜头关联不强行复制。原字幕审核证据留在导入溯源中，正文作为可编辑字幕恢复，不冒充目标项目审核。
- 导入保留原始工程包溯源与归档哈希；相同 request_key/文件重试返回原候选，异文件重用请求标识拒绝。归档恢复仍是候选，需要明确采用。
- 实测跨项目恢复后重新编辑、预览成功；不依赖原项目镜头或生成记录。完整测试还需覆盖独立数据库/存储服务迁移和更大文件，不以该测试替代全部规模验收。
- 页面新增「导出完整归档」，恢复入口同时接受 ZIP 和 JSON。支持 File System Access 的浏览器直接将响应流保存到文件；其他浏览器仅允许 512 MiB 内存下载，较大归档明确提示换用支持直接保存的浏览器。上传当前仍使用单次 multipart，尚非可恢复大文件上传任务。

## 工具与页面接入增量

- 现有系统工具目录增加可信代码注册接口，声明参数 schema、分组、版本和可选审阅执行器。新工具可注册 handler，无需再追加中央执行函数分支；重复身份和缺少审阅处理器拒绝注册。
- 工程组提供 `engineering.read/propose/preview` 三个入口，供现有 Agent 或独立 `ToolContext` 调用。读操作使用项目权限；写候选和预览要求上下文已关联相同作品，并复用工程服务的版本、权限、幂等和固定修订校验。没有向 Agent 暴露自动采用工具。
- 工具结果转换为 JSON 数据，领域状态仍在工程服务；通过真实数据库测试验证不建立 AgentRun 也能提出候选，API 读到同一候选。现有 Agent 回归通过。尚未进行付费模型驱动的制作闭环验收。
- 「工程内容」增加新建工程文档入口，名称必填，支持图像、音频、动态合成空白文档，以候选方式保存。浏览器验证名称、类型和不自动采用；不是完整图层拖拽/曲线编辑器。

### 仍不能宣称完成的设计范围

- 多条工作时间线的一次原子修改仍被明确拒绝；现支持一条时间线与多份原生文档共同采用。整作品 CAS 防止覆盖，但没有分支合并或不相交修改自动合并。
- 端口引用替换尚未提供“只修改共享端口中某一个使用实例”的自动拆分操作；不能把端口替换当成逐实例修改。
- 影响报告仍是固定修订与输出根级别，尚不计算画面时间范围、音画同步或业务语义影响。
- 原生编辑页面只覆盖基础参数，并未实现完整图层、效果、曲线编辑器；算子执行范围以注册能力和预检为准。

- 工程工具已独立于 Agent 调用并通过数据库测试，但未实现完整多 Agent 长流程编排、动态工具发现与制作闭环。

以上是实际剩余边界，不以已完成的基础预览或页面入口替代整个目标验收。

## 使用实例编辑与影响报告增量

- 新增 `instance.retarget`：指定文档固定修订、实例 ID、输入位置和原固定引用，给选定实例分配独立输入端口。共享端口的其他图层/片段不变，原素材不变；可与同批子文档修改共同提交候选，仍受作品基线和原子事务约束。
- 版本化使用实例适配器目前支持图像/合成文档的 source、mask，以及音频文档片段的 source。扩展类型可注册适配器；未知格式拒绝解释。一次命令支持多个不同实例输入；同一文档的重复写入仍须整理为一次命令。
- 影响报告增加实例输入的前后固定引用和可读名称。若一个文档同时存在多个修订，报告明确标注无法唯一配对，不猜测关系。仍不计算画面时间范围、音画同步和视觉质量。
- 页面在候选影响审阅中显示文档、使用位置和引用修订变化。当前入口是工程命令/API/工具加审阅展示，尚未增加完整的图层/音频可视化选择编辑器。
- 真实数据库参数化验证图层源、蒙版、合成图层和音频片段四种使用位置，覆盖共享引用隔离、同批候选解析、历史不变、原引用竞争、重复位置拒绝、缺失目标回滚与幂等重试。工程实例/原生持久化/工具回归共 9 项通过；隔离浏览器验证可读影响展示及原工程流程。

## 多时间线原子采用增量

- 一个候选允许修改多条工作时间线，也可与原生文档修改组成同一变更。每条时间线固定自己的文档修订、编辑基线和预览；重复写同一条时间线拒绝。
- 候选内部保留主时间线兼容已有接口，其余写入保存在 `timeline_update.additional_updates`。预览可指定 `output_id: timeline:<id>`，任务证据按输出隔离；主时间线旧接口保持有效。
- 采用时逐条检查真实预览和编辑基线，在同一数据库事务中保存所有时间线、原生文档采用状态与作品提交。任何一条冲突时整批回滚；历史不覆盖。不等同于多个用户的自动并行合并。
