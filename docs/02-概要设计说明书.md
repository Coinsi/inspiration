## 1. 引言

### 1.1 目的
确定系统**怎么搭**:总体架构、技术选型、模块划分、核心机制的概要方案、部署形态与关键数据流。为详细设计(ER 模型、API 契约、状态机)提供框架约束。本文不涉及表字段级与接口签名级细节(留详细设计)。

### 1.2 设计原则
1. **开闭原则优先**:一切易变外部能力走策略 + 注册中心,核心对修改关闭。
2. **模块化单体(Modular Monolith)**:V1 单机自托管,按限界上下文切模块,不上微服务,保留向服务化演进的接缝。
3. **领域驱动分层**:接口层 / 应用层 / 领域层 / 基础设施层,依赖单向向内。
4. **版本与溯源是横切内核**:可版本化能力以共享内核提供给各模块。
5. **异步优先**:一切耗时/外部调用(生成、解析、AI 拆解、转码)走任务队列。

| 层 | 选型 | 理由 |

## 4. 核心机制概要设计

### 4.1 策略注册中心(开闭原则的基础设施)
- 每类扩展点对应一个 `Registry`(generation / parser / decomposition / consistency / …)。
- 具体策略以装饰器自注册:`@registry.register("jimeng")`,携带元信息(名称、能力声明、是否启用)。
- 应用层只向 Registry 按 **名称 + 能力匹配** 取策略,绝不 import 具体实现。
- 供应商启用状态与密钥由 `platform` 模块按项目管理(加密存储)。
```
请求 →[能力协商]→ Registry.resolve(type, name, required_caps) → Strategy 实例 → 执行
```

### 4.2 生成任务编排(异步驱动)
生成是**过程**,以任务生命周期建模,图像与视频共用同一编排,仅策略不同:
```
API 提交生成
  → [配额校验] [权限校验] [能力协商] [成本预估]
  → 创建 GenerationJob(pending) + 冻结输入快照(溯源雏形)
  → 入 Celery 队列(按供应商限流)
  → Worker: provider.submit() → submitted
  → Worker: provider.poll()/webhook → running → succeeded/failed
  → 成功:产物经 CAS 落 MinIO,生成缩略图,写不可变 Generation 溯源记录,挂为资产变体
  → 失败:记录原因,支持重试/部分续跑
```
关键:**输入在入队即冻结**(提示词内容、参数、模型、参考图版本),保证溯源不可变(FR-04-06)。

### 4.3 版本 / 基线 / 溯源内核
- **实体二分**:可版本化实体 = `主记录(身份)` + `版本记录(内容快照)`,版本记录不可变。
- **引用模式**:引用边携带 `ref_mode(floating|pinned)` 与 `pinned_version_id`。
- **基线**:`Baseline` + `BaselineItem`,一次冻结一整套实体的指定版本;支持回溯、对比、并行方案。
- **溯源**:`Generation` 记录冻结全部输入指针,independent 于后续版本演进。
- **存储**:二进制走 **内容寻址(CAS)**,`Blob(hash, uri)`,版本仅持指针,天然去重。

### 4.4 依赖图与影响分析
- 统一 `Relation(src, dst, type, ref_mode)` 边表,承载改编/组成/引用/复用/组装五类关系。
- 影响分析 = 沿边反向遍历:给定被改实体 → 找出引用它的下游 → 区分 `floating(已波及)` / `pinned(可升级)` → 输出清单 → 批量重生成(FR-09-04)。
- 图可视化由前端 React Flow 消费该边表。

### 4.5 提示词 BOM 组合
```
镜头最终 Prompt = Σ(引用角色.提示词片段)
               + Σ(引用场景/道具.提示词片段)
               + 场景描述
               + 风格模板(ST)
               + 镜头特定描述
               + (一致性策略注入的参考/触发词)
```
- 组合在**生成提交时**求值并快照进溯源;支持人工覆写(覆写也版本化)。

### 4.6 一致性策略
- 端口 `ConsistencyStrategy`:`prepare(shot, refs) → 注入提示词/参考图/LoRA 配置`。
- 三实现可切换:纯提示词拼装 / 参考图 reference / LoRA;角色/场景资产持有"视觉身份"供策略消费。

### 4.7 权限网关与审计
- 接口层中间件:解析 JWT → 定位 `project_id` → 校验 `role × action`(策略表驱动)。
- 受控动作:锁定/定稿、建基线、触发生成、审批、配额管理(FR-10-03)。
- 所有写操作 + 生成触发统一经 **审计装饰器** 落 `AuditLog`。

## 5. 数据存储概要(逻辑视图)

> 字段级 ER 图留详细设计;此处给出聚合与归属。

```
Project(隔离根)
 ├─ Membership(User, Role)            ── identity
 ├─ Novel/Outline/Script/Scene        ── narrative(均可版本化)
 ├─ Asset(Character/Prop/Location/…)  ── asset(蓝图,均可版本化)
 │   └─ VisualIdentity                ── consistency
 ├─ Prompt / PromptFragment           ── prompt(可版本化)
 ├─ Shot                              ── shot(production_status)
 │   ├─ AssetRef(ref_mode, pinned)    ── 引用边
 │   └─ Generation(变体, 溯源)         ── generation
 ├─ GenerationJob                     ── generation(任务生命周期)
 ├─ Timeline → TimelineItem           ── timeline
 ├─ Cut(整片, 基线化)                  ── timeline
 ├─ Baseline → BaselineItem           ── versioning
 ├─ Review → Annotation/Revision      ── review
 ├─ Blob(CAS) / Thumbnail             ── storage
 ├─ ProviderConfig(加密密钥)           ── platform
 └─ AuditLog                          ── identity
```
通用横切字段(可版本化实体):`id, project_id, code, status, current_version_id, created_by, created_at, deleted_at(软删)`。

## 6. 关键数据流(概要时序)

**① 小说导入 → AI 拆解**
```
上传文件 → 解析策略.can_handle→parse → 结构化文档入库
 → (异步)AI拆解策略: 章节→建议场次/镜头, 抽取实体草稿
 → 人工确认 → 落场次/镜头/资产卡
```
**② 镜头生成 → 定版**(见 4.2),产物挂为镜头变体。
**③ 评审 → 返修**
```
发起评审 → 批注(画面框选/视频时间码) → 通过|打回
 → 打回: 生成 Revision 轮次, 镜头回"返修"态
 → 通过: 钦定代表版, 镜头转"定版"
```
**④ 成片基线**
```
镜头定版片段 → 排入 Timeline(顺序/入出点/转场)
 → 创建 Cut 基线(粗剪/精剪/定剪): 冻结全部镜头版本 + 排序 + 引用资产版本
 → 可复现 / 可对比 / 可回溯
```

## 8. 部署架构(单机自托管,决策 D4)

```
                 ┌─────────────── Docker Compose 单机 ───────────────┐
   浏览器 ──HTTP──┤ web(Nginx+React)  api(FastAPI)  worker(Celery)    │
                 │        │              │     │           │         │
                 │        └──────────────┘     │           │         │
                 │   postgres(+pgvector)   redis(broker)   minio(S3)  │
                 └───────────────────────────────────────────────────┘
```
- 单 `docker-compose.yml` 拉起全部服务,一键自托管。
- 模块化单体便于单机部署;`project_id` 隔离已在模型内置,未来切多租户云端无需重构数据模型,仅调整部署与扩展策略。
- 备份:Postgres 逻辑备份 + MinIO 卷快照。

## 11. 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 即梦 API 能力/配额/计费变动 | 生成链路 | 策略隔离 + 能力声明,变动只改适配器 |
| AIGC 一致性效果不达预期 | 核心卖点 | 一致性三策略可切换,A/B 验证择优 |
| 生成任务长耗时/失败 | 体验 | 异步 + 重试 + 部分续跑 + 进度可见 |
| 版本/基线模型复杂 | 工期 | 横切内核统一实现,先打通修订线+基线主干 |
| 大文件存储膨胀 | 成本 | CAS 去重 + 缩略图/(EXT)代理转码 |
