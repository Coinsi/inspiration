# 账户、成员权限与第三方登录扩展

## 本次交付

- `/register`：沿用登录页的视觉布局，用户名、昵称、邮箱、密码和确认密码；注册成功后登录到项目列表。
- 注册接口校验重复用户名/邮箱，邮箱统一小写；新密码至少8字符、最多72个UTF-8字节，避免 bcrypt 截断造成歧义。旧密码仍可登录。
- 右上角个人设置：昵称、简介、头像上传/移除、账户安全、外观和语言。头像限制5 MB、静态 JPG/PNG/WebP，转成256px WebP缩略图，不接收任意外链或SVG。账户缩略图随资料保存在数据库中，不占项目素材引用。
- 修改密码要求当前密码。`auth_version` 增加后所有旧JWT（包括媒体链接中的JWT）失效；返回新JWT保持当前页面登录。已有JWT无 `ver` 时按0处理，保留迁移兼容性。
- 成员页面显示姓名、用户名、头像和所有者；按已注册用户名添加，确认调整角色、移除成员。只读成员看不到管理操作，后端仍独立验证权限。
- 项目级锁串行化成员变更，锁内重新检查管理员身份。所有者不可降权或移除，管理员不能误移除/降权自己。保留原 `user_id` 添加接口兼容性，但同样执行保护。
- 账户切换清空前端查询缓存，避免显示上一个用户的项目数据。

## 第三方登录扩展边界

`user` 是稳定的业务用户，项目成员、素材和作品继续引用它。密码允许为空，为将来的第三方独立注册账户预留空间。

新增 `user_identity`：`user_id`、`provider`、`issuer`、`subject`。唯一键为 `(provider, issuer, subject)`，一个用户可以关联多个身份。邮箱不作为自动绑定或合并依据，不保存第三方访问令牌。

`app/modules/identity/external.py` 提供 `ExternalLoginAdapter`、`VerifiedIdentity` 和已绑定身份登录入口。该入口只接收服务端适配器验证结果，未绑定/已禁用账户拒绝登录，统一签发包含安全版本的JWT。当前没有对外开放任何OAuth回调或身份绑定接口。

`GET /auth/providers` 当前返回空供应商列表；`GET /me/security` 返回本地密码是否存在和已绑定供应商的基本信息。前端不会显示未启用的第三方登录按钮。

以后接入具体供应商时需完成：

1. 服务端配置固定的提供商、回调地址和密钥。实现授权地址、授权码交换及供应商身份验证，禁止前端提交的身份声明直接进入登录函数。
2. 为登录/绑定区分一次性流程，服务端保存并验证 state、PKCE、nonce，限定有效期，消费后不可重用。OIDC校验签名、issuer、audience、时间等；其他协议使用对应官方验证方式。
3. 已绑定身份直接登录；未绑定身份进入显式开户/绑定流程。绑定已有账号要求重新验证当前用户，不能根据邮箱自动合并。
4. 解绑要求重新认证，且至少保留一种可用登录方式。供应商变化不改变项目权限。
5. 对回调重放、错误issuer、绑定冲突、账号禁用及无本地密码账户添加端到端测试。

## 尚未接通的能力

邮件验证、忘记密码的邮件恢复、邮箱修改、具体第三方供应商回调/绑定/解绑尚未启用。注册邮箱目前不能视为已验证身份。外观和语言仍按当前浏览器保存。成员添加使用已注册用户名，不发送邮件邀请。

## 数据迁移

`0021_account_identity` 为已有用户补充空简介、空头像和安全版本0，建立独立身份表。不会改变用户名、密码、项目和成员。降级前如存在无密码用户会拒绝执行，避免破坏其登录方式。
