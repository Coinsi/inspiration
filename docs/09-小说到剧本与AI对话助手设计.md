# 09 · 小说→剧本正文 与 贯穿式 AI 对话助手设计(草案)

| 项 | 说明 |
|---|---|
| 主题 | ① 补齐「小说 → 剧本正文」一等环节;② 剧本→人物/场景资产直接拆解;③ 资产 AI 生图入口;④ 贯穿全流程、可改一切的「AI 对话助手(侧边栏)」 |
| 位置 | 小说 → 章节 → **【新增】剧本正文** → 场次 → 镜头 → **资产(可 AI 生图)** → 生成 → 成片 |
| 关系 | 复用 narrative 模块、M1 版本内核、M2 抽实体落资产、M4 生成(即梦)、LLM 策略(`cloud_llm`/mock);剧本正文成为场次/镜头**及人物/场景资产**的派生来源 |
| 状态 | 🟡 待评审(草案) |
| 决策已锁定 | 剧本正文 = **分块结构化(typed blocks)**,且为**一等公民**(可读/可编辑/可导出);剧本可直接拆解人物/场景资产;资产有 **AI 生图**入口;**侧边栏 AI 助手可交互修改任何对象** |
| 设计参照 | Laper.ai —— 借鉴其"对话式可编辑 + 处处可改 + 多 Agent 顾问"体验,但**补上 Laper 没有的"出图出片"**(本平台核心差异化) |

## 一、背景与缺口

现状链路(代码:`backend/app/modules/narrative/service.py`):

```
import_novel(小说) → chapters(章节) ──decompose_chapter()──▶ 场次+镜头(直接产出)
```

`Script` 当前仅作"场次容器",**没有真正的剧本正文形态**,也**没有对话式修改**(`decompose_chapter` 为一次性出结果,全模块无 chat/refine/revise 逻辑)。

缺口:
1. **缺「小说→剧本正文」环节** —— 章节被直接拆成场次,缺少可读可改的标准剧本文本(场景头/动作/对白)。
2. **剧本不可编辑/不可导出** —— 没有专业剧本编辑器,也无 Fountain/PDF 等导出。
3. **剧本→资产链路弱** —— 现有抽实体(M2)从章节抽,未从剧本正文直接拆人物/场景,且不可对话修改。
4. **资产缺 AI 生图入口** —— 拆出的人物/场景只有文字,没有"就地 AI 生成形象图"的地方。
5. **缺贯穿式对话修改** —— 无法"告诉 AI 怎么改、多轮迭代、再落库",且未覆盖到全部对象。

## 二、目标链路

```
小说 → 章节 ──(AI 改编)──▶ 剧本正文(可编辑/可导出,分块) ──(AI 拆解)──┬──▶ 场次 + 镜头
                                  ▲ 一等公民                          └──▶ 人物/场景 资产 ──▶ AI 生图(即梦) ──▶ 生成/成片
        ┌──────────────────────────────────────────────────────────────────────────────┐
        │  侧边栏 贯穿式 AI 对话助手:用户可对话修改 任意对象(剧本/场次/镜头/资产/提示词/生图)   │
        └──────────────────────────────────────────────────────────────────────────────┘
```

- `Script` 升级:从"场次容器"→ **承载可编辑/可导出的剧本正文**。
- 场次/镜头 与 **人物/场景资产** 均**从剧本正文派生**(decompose / extract_entities 输入由"章节"切换为"剧本正文")。
- 拆出的资产可在**资产详情就地 AI 生图**(复用 M4 即梦 + 资产概念图;参考图发送沿用 base64 物化方案,见 `jimeng._materialize`)。
- AI 助手以**侧边栏**形态贯穿,作用域 = 当前对象,**可改一切**。

## 三、剧本正文数据形态(分块结构化)

剧本正文 = **有序的 typed blocks**,而非富文本一坨。

| 块类型 `block_type` | 对应剧本元素 | 关键字段 |
|---|---|---|
| `scene_heading` | 场景头 `INT./EXT. 地点 - 时间` | `int_ext`、`location`、`time_of_day` |
| `action` | 动作 / 场景描述行 | `text` |
| `character` | 角色提示(对白前的角色名) | `character_name` |
| `dialogue` | 对白 | `text` |
| `parenthetical` | 括号表演提示 | `text` |
| `transition` | 转场(CUT TO 等) | `text` |

选择理由:① 编辑器可做专业剧本格式;② AI 能精准定位("改第 3 个场景的对白");③ 可**无损派生**场次/镜头;④ 可序列化导出 **Fountain**(行业标准纯文本剧本)互通。

> 详细字段/枚举/索引在「详细设计·数据模型」阶段定稿;此处仅锁定"分块"方向。

### 设计理念借鉴(Laper.ai)

| Laper 做法 | 本平台采纳/超越 |
|---|---|
| "AI 干杂活,人专注艺术" | 采纳:AI 接走格式化/拆解/初稿,人定创意 |
| 多 Agent「顾问团」(好莱坞/古典/英雄之旅/诺兰风格…) | 采纳:对话助手支持**可选风格/角色**,对话引导创作 |
| 处处可编辑(每张卡片就地编辑) | 采纳:剧本/资产/镜头均就地可改 + 侧边栏 AI 改 |
| 实时协同(评论/反馈,CRDT) | 暂以现有项目级协作为主,实时协同列为后续扩展点 |
| **止步于文字(无出图出片)** | **超越:剧本→资产→AI 生图→出片,是本平台护城河** |

## 四、模块与策略设计(方向)

- **改编策略** `ScriptAdaptationStrategy`(可插拔,遵循开闭):`adapt_chapter_to_script(chapter) → blocks`。默认 mock 回落;`cloud_llm` 覆盖出完整剧本块。复用 `_llm_config` / `_strategy` 既有取配置逻辑。
- **拆解输入切换**:`decompose` / `extract_entities` 从"章节正文"改为可接"剧本正文",派生**场次/镜头 + 人物/场景资产**。
- **剧本导出**:blocks 序列化为 **Fountain**(行业标准),并支持 PDF/纯文本导出。
- **资产 AI 生图**:资产详情页提供"AI 生图"入口 → 复用 M4 生成编排(即梦)产出资产概念图;若启用参考图,按 `09 设计` 的 base64 物化方案发送(收口在 `jimeng._materialize`)。
- **版本联动**:剧本正文 / 资产 / 镜头的生成、编辑、AI 改动**走 M1 版本内核**(快照/回滚/锁定),天然可回退。

## 五、侧边栏「贯穿式 AI 对话助手」设计(方向)

定位:一个**侧边栏**常驻助手,**作用域 = 当前正在看的对象**,用户可对话修改**一切**(剧本/场次/镜头/资产/提示词/生图参数)。

- **会话模型**:`AssistChat(target_type, target_id, project_id, messages[])` —— target 覆盖 `script/scene/shot/asset/prompt/generation`。
- **可改一切的统一回路**:用户指令 + 对象当前状态 + 上下文 → AI 产出**结构化修改建议**(候选版本 / diff / 生图参数)→ 用户接受/拒绝/继续追改 → 接受则落库 + 触发版本快照。
- **对象适配器**:每类 target 注册一个"读当前态 + 应用建议"的适配器,新增对象类型即插即用(开闭原则)。
- **风格/角色**:借鉴 Laper 顾问团,助手可选风格(如"好莱坞/诺兰风格"),影响系统提示。
- **流式**:SSE 流式输出;复用现有 SSE 能力。
- **策略复用**:走 `cloud_llm`;无云 key 时 mock 也能跑通验收。
- **权限/审计**:接受类操作受项目 RBAC 与审计约束(与既有一致)。

## 六、分期建设(每期可独立验收)

| 期 | 范围 | 验收口径 | 状态 |
|---|---|---|---|
| **P1** | 剧本正文模型(blocks)+ 小说→剧本 AI 改编 + 正文读写 API + **Fountain 导出** | 导一篇小说 → 生成可读剧本 → 导出 Fountain | ✅ 已交付验收 |
| **P2** | 剧本正文 →(派生)场次/镜头 **+ 人物/场景资产** | 剧本 → 场次/镜头/资产 一致落库 | ✅ 已交付验收 |
| **P3** | 侧边栏贯穿式 AI 对话助手(会话+对象适配器+ops 预览+应用+版本联动) | 在剧本/场次/资产上多轮"告诉 AI 怎么改"并落版本可回退 | ✅ 已交付验收 |
| **P4** | **资产 AI 生图入口**(复用 M4 即梦;可选参考图 base64) | 在人物/场景资产页点"AI 生图"出概念图 | ✅ 已交付验收 |
| **P5** | 前端:分块剧本编辑器(可编辑/导出)+ 常驻侧边栏 AI + 资产生图 UI | 编辑器 + 侧边栏改一切 + 资产出图 live 通过 | ✅ 已交付验收 |

> P5 落地说明:新页面 `pages/ScriptEditor.tsx`(路由 `scripts/:scriptId`)—— 分块编辑(6 类块按专业剧本排版:场景头加粗大写/角色居中/对白缩进)+ 悬浮工具条(改类型/插块/删块)+ 未保存检测 + Fountain 下载 + 「拆场次/镜头」「抽实体」派生浮层。通用组件 `components/AssistPanel.tsx`(复用最近会话,发指令→提议卡→应用→失效刷新),挂在剧本编辑器右栏与资产详情「AI 助手」tab。拆解工作台章节头加「AI 生成剧本」直达编辑器;`GenerationPanel` 资产生图加「带参考图」开关。live 验收:真实云 LLM 把《逆天邪神》章节改编成 112 块剧本(`EXT. 琅缳山·绝云崖 - 昏暮`),AI 助手对话改标题→应用生效,抽出 23 个实体落库为资产,带参考图出 4 张概念图。

> P4 落地说明:资产生图复用既有 `POST /assets/{id}/generate`(target_type=asset 已支持名称+视觉身份拼提示词)。本期接通**参考图**:`submit` 按供应商 `max_reference_images` 收集资产参考图(仅存 blob_hash 进轻量快照),`run_job` 提交前**物化为 base64 data URI**(收口在 `service._materialize_references`,fs/MinIO 通用,将来可改预签名 URL),`jimeng.submit` 放入 `reference_images`。`GenerateIn.use_references` 可关;`Generation.input_refs.references` 记录发送溯源。

> P3 落地说明:对话修改采用「**结构化 ops**」而非整段重写 —— AI 产出 `set_title/replace_block/insert_block/delete_block/move_block`(剧本)或 `set_field`(场次/镜头/资产),服务层逐条校验 + **dry-run 预览**,用户接受才 `apply`(原子应用 + `VersioningService` 版本快照,可回退;重复应用拒绝 409)。对象适配器注册表已支持 `script/scene/shot/asset`,新增对象类型即插即用。引擎 `mock`(离线)/`cloud_llm`(复用项目 LLM 配置)。

## 七、决策(已锁定 —— 取最兼容现有代码的方案)

1. **blocks 存储 → `script.content_blocks` JSONB 列**(✅ 锁定)。复刻 M3 `shot.storyboard` 的 JSONB 模式(迁移 `0002`),改库最小、PG 原生、AI 可按 block `id`/序定位。独立表方案留到结构复杂度真正需要时再升级。
2. **改编策略 → 复用 `DecompositionStrategy`,新增 `adapt_chapter_to_script()`**(✅ 锁定)。基类给默认实现(mock 自动可用),`cloud_llm` 覆盖出完整剧本块 —— 复刻 `suggest_storyboard_shots` 的扩展方式,不另起注册中心;沿用 `_strategy()` 选择逻辑。
3. **派生方向 → 一次派生、各自演进**(✅ 锁定)。沿用 `apply_scenes` 的 append 语义;可重复触发(追加),不做强同步。
4. **AI 改动落库 → 整体保存 + M1 版本快照**(✅ 锁定)。P1 先做整篇保存;版本联动随 P3 对话助手接入。
5. **对话助手作用域上线顺序**:先接剧本正文,P3 起按对象适配器逐类推广(scene/shot/asset/prompt/generation)。

### block 数据结构(P1 定稿)

```jsonc
// script.content_blocks: 有序数组
[{ "id": "<uuid>", "block_type": "scene_heading", "text": "INT. 咖啡馆 - 日" },
 { "id": "<uuid>", "block_type": "action",        "text": "Oscar 推门而入,环顾四周。" },
 { "id": "<uuid>", "block_type": "character",     "text": "OSCAR" },
 { "id": "<uuid>", "block_type": "dialogue",      "text": "让我告诉你关于 Mimi 的事……" }]
```

`block_type ∈ {scene_heading, action, character, dialogue, parenthetical, transition}`。P1 统一以 `text` 承载(场景头的结构化 int_ext/location/time 留待后续细化);导出 Fountain 时按类型渲染。

## 八、追加:设定库(故事圣经)✅ 已交付验收

AI 通读整本小说,沉淀**可扩展分类**的设定库(预置 8 类:世界观/力量体系/势力组织/人物/地点/物品道具/术语/大事记,category 存自由字符串)。

- **数据**:`setting` 表((project,novel,category,name) 唯一,source_chapters 溯源)+ `setting_extraction` 任务表;迁移 `0005`。
- **一键全书提取**:`POST /novels/{id}/extract-settings` → **后台线程**逐章跑(本地 eager 环境可用):每章把"已有设定名录"喂给 LLM,**同名条目返回合并补全后的完整版整条覆盖**(增量补全),新名字新建;每章 commit,进度可轮询(`/latest`)、可取消、中断重发即续跑。策略层 `extract_settings()`(mock 离线 / cloud_llm)。
- **前端**:侧边栏「创作 → 设定」;左分类导航(8 类+动态扩展)/右设定卡片;提取进度实时(边跑边长出来);卡片可编辑/删除/**转资产**(人物/地点/物品 → character/location/prop);AI 助手适配器已注册 `setting`(可对话改设定)。
- **验收(live,真实云 LLM)**:《逆天邪神》(1765 章)发起提取,第 1 章即产出 9 条铺满 8 类;跑数章后 20 条、**5 条跨章合并**(云澈条目正确融合第 1 章坠崖与第 2 章转世萧澈的信息,source_chapters=[1,2]);取消任务生效(2/1765 停止)。
- **S3 设定注入** ✅ 已交付验收:`settings_context()` 组装「该章出现的设定 + 全局世界观/力量体系」(分组、单条 240 字、总量 3500 字截断)→ ① `generate_script_from_chapter` 注入改编提示词(「已确立的故事设定,改编必须遵守」);② AI 助手对剧本对象改稿时注入 `story_settings` 进对象状态。验收:第 2 章带 3458 字设定上下文生成 97 块剧本(51s),萧澈/夏倾月/萧烈人设与设定库一致。
- **提取并发**:波次并发(1/2/4/8 可选)+ 波内同名冲突由 `merge_setting_versions`(LLM)融合,4 章并发 4 实测 102s(提速 ~2.5×)。
- **检索**:设定页支持名称/内容搜索 + 章节筛选(单章或 5-8 区间);出自章节按连续区间压缩显示(1-8、11-12、14)。
