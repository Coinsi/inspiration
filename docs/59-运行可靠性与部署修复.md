## 维护命令

从 backend 目录运行，使用目标环境的 `.env`。备份目的目录必须不存在；素材按哈希校验，整份数据库和对象清单使用同一数据库快照。

```text
python -m app.maintenance inventory
python -m app.maintenance audit
python -m app.maintenance backup /backup/new-snapshot --pg-dump /path/to/pg_dump
python -m app.maintenance verify /backup/new-snapshot
```

`--database-only` 显式生成不含媒体的备份。`--allow-missing` 用于存在历史缺失时抢救可读文件：清单列出缺失对象，验证结果为 partial，禁止完整素材恢复。普通备份遇到缺失立即失败，不生成完成清单。

恢复应先在独立空数据库演练：用匹配版本的 pg_restore，提前准备原库使用的扩展。schema 级转储包含 CREATE SCHEMA public，而新数据库默认已有 public；可以用 `pg_restore -l` 生成清单，仅跳过已有 public 的 SCHEMA 创建条目，然后用 `-L` 加 `--no-owner --no-acl --exit-on-error` 恢复。不要把恢复命令指向现用数据库。

完整备份的数据库恢复后，在恢复环境配置目标存储，再执行：

```text
python -m app.maintenance restore-objects /backup/new-snapshot
python -m app.maintenance audit
```

恢复命令先核对数据库所需的全部对象，再写入配置的存储并更新地址；哈希和项目引用保持不变。供应商密钥解密仍需要原 `CREDENTIALS_FERNET_KEY`，配置应单独安全保管。

## 部署与仍未完成的边界

- Compose 仍是本地开发模板。公网部署需要专用密钥、TLS、网络隔离及受控注册策略，不能直接使用示例凭据。
- 代理覆盖 X-Forwarded-For；在 API 配置 FORWARDED_ALLOW_IPS 为可信反向代理的地址/网段，避免多用户都被按代理地址计数。不要在可直接从公网访问的 API 上信任任意转发地址。
- 备份命令已提供，但定期备份、异地副本及告警需要部署时安排；新增 CI 尚未推送到远端运行。
- 物理垃圾回收、跨项目存储容量配额及真实长视频多用户压测仍未完成。本轮保留回收站、历史版本和引用保护，未自动删除任何原素材。
- 云端视频/图片模型协议、真实生成计费与失败续查仍按原 TODO 暂缓。
