# 原有故事流程与剧本保护

## 修复

1. 章节改编、章节拆解、实体提取先检查章节所属项目与原书状态，错误项目不进入模型调用。场次列表验证剧本归属，设定关联小说也校验项目。
2. 剧本应用场次时，若请求未指定章节，继承剧本的来源章节，保障小说/章节筛选能找到派生镜头；已有剧本可保留被回收原书的来源记录。
3. 设定转资产使用资产编辑权限，避免仅有写作权限的成员绕过原有资产权限。
4. 纯文本导入支持带BOM的UTF-8和“第一章海边”这类无空格章节标题。
5. 剧本正文返回内容修订摘要；编辑器保存时携带所加载摘要，服务端锁定正文后校验，拒绝覆盖其他页面或助手的新稿。锁定剧本不能通过正文接口修改。
6. 未保存剧本按当前用户、项目、剧本保留浏览器草稿，刷新后可恢复；请求刷新不覆盖正在编辑的文字，保存请求期间的新输入也不被迟到结果覆盖。冲突保留两份内容，由用户核对后载入/保存。支持Ctrl/Cmd+S。
7. 未保存正文时暂不允许按旧服务器正文拆场次、提取或导出；本地草稿写入失败和服务器读取失败有明确状态。

## 实际验证

`test_story_pipeline.py` 使用真实TXT导入与隔离数据库，走章节→设定上下文→受控改编→场次→章节筛选下的分镜→设定转资产→正文保存→冲突拒绝→Fountain导出。受控改编验证正确文本和设定传入，不代表模型改编质量。

另一项验证错误项目的章节、剧本、设定在调用模型前被拒绝，以及写作者不能转资产。此前没有覆盖这组原有流程的项目边界。

`script-draft-live.mjs` 创建专用QA剧本，浏览器实际修改、刷新、恢复草稿，另一个写入者更新服务器，再保存旧稿得到409；确认浏览器草稿与服务器新稿均保留，载入后再次编辑保存成功。证据目录 `platform-rebuild-batch14`。

## 明确边界

本轮合并工作区状态已通过85项后端回归与前端生产构建；浏览器确认Ctrl/Cmd+S走相同的修订校验保存流程。没有提交代码。

正文摘要冲突保护对新编辑器生效；为兼容旧客户端，API暂允许省略expected_revision，所有外部写入端应逐步迁移。还没有新增完整的正文逐次历史浏览与三方合并界面。设定全书提取的后台恢复、模型质量和长篇压力测试仍需专项完善。

只读核对用户项目当前启用的是gpt-5.5文本与gpt-image-2图像配置，未配置可验收的视频或音频生成供应商；这两类云端生成不标记为完成，也不影响本地转写、素材处理和剪辑交付。
